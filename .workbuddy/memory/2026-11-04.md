# 2026-11-04

## 微信附件 grep 式检索（已完成）

- 新增 `assets/js/wechat-document-search.js`（`window.RPHubWeChatSearch`，纯函数 `parseQuery` / `scan`）：
  支持 `+必含 / -排除 / "短语" / A ~30 B 邻近 / /正则/i / case:on`，中文标点也当分隔符。
  扫描按块进行、保留 80 字符重叠；命中按绝对位置聚类（间隔 ≤220、跨度 ≤900），
  多词按 `idf × log(tf)` + 短语/邻近/标题加权，最后按 `min(24, limit×4)` 回读块拼摘录。
  摘录与 `offset/end` 严格对应原文切片（有断言守住）。上限：8 词、300 字符表达式、160 字符正则、
  40 次/块、20000 段出现、4000 ms 预算，触顶标 `truncated` 并显示实际扫描块数。
- `wechat-documents.js`：`search` 改为薄封装 + 新增 `locate(item, charOffset)` 按字符定位块。
- `29-wechat-documents.js`：`tool_list_documents` 补「已整理 a/b 块」「目录 n 条」；
  `tool_search_document` 新增 `limit/startChunk/endChunk`，`messageId` 可选（省略或 `*` = 最近 10 个附件，
  命中行必须带 `#消息ID｜文件名` 否则模型无法接着读）；`tool_read_document` 新增 `startChar`。
  提示词写明 list → search → read 顺序与语法。
- 文档：新建 `docs/wechat-document-search.md`；同步 `wechat-documents.md`、`MODULES.md`、
  `ARCHITECTURE.md`（新增 3.45/3.46 行）、`wechat-and-RP.md`、`wechat-tool-activity.md`。
- 验证：Node 文档专项 25/25（新增 7 项），总 99/99；浏览器文档 25 项 + 微信整体冒烟通过，零 JS 错误。
  性能：1.1M 字符 459 块随机语料 8–12 ms（内存读块）；重复语料 60–110 ms。
