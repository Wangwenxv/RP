# 世界自主叙事与玩家决定权交接

更新：2026-11-07。沿用工程原有 UI，修改提示词与上下文来源，不新增叙事模式开关。本工程不是 CWUI。

> 后续微信自问自答样例已补程序交接：本 RP 回合只接受一次主动联系，成功即结束自动续写；不解析嵌套消息列表。见 [主动微信交接修正](./wechat-player-handoff.md)。

## 目标

角色卡定义一个人物及其背景，模型同时扮演非玩家人物，并承担有限的世界叙述。角色和玩家都生活在世界里，镜头根据事件的因果与人物处境移动，不把任何一方固定为每轮中心。

玩家的言行与选择由玩家决定。这个边界限制的是模型控制玩家的行为，不要求整个世界等待玩家：分开后，角色可以与朋友相处、学习、办事，也可以因为自己的事情主动联系玩家。需要玩家回应时，只把相关互动停在回应点。

这补充了上一轮的[玩家决定权约束](./player-agency.md)，不是取消“防抢话”。

## 当前规则

| 情境 | 模型可以推进的内容 | 留给玩家的内容 |
| --- | --- | --- |
| 玩家与角色分开，各自忙碌 | 角色及其他 NPC 的独立活动、对话与有依据的内心，可以形成完整片段 | 玩家未写出的后续动作、台词与心理 |
| 角色想分享、关心或询问 | 按人设产生联系动机，通过实际微信工具发送角色消息 | 玩家的阅读、回复、承诺与行动 |
| 出现需要玩家参与的事情 | 让事情自然发生，传达情况、请求或线索 | 玩家是否参与、如何处理、是否成功 |
| 玩家拒绝或暂不决定 | NPC 对拒绝的反应、另找办法或继续自己的事务 | 不能把拒绝改成答应，也不能跳到玩家配合后的结果 |
| 叙述者展示玩家不在场的场景 | 描写实际发生的 NPC 事件 | 玩家和其他人物不会因此自动知情 |
| 玩家已经明确做出一步 | 承接这一步的客观后果和其他人的反应 | 不自动补完下一步 |

独立片段的长度由场景需要决定。面对玩家的直接互动只写当前这一轮，不代写多轮问答。角色发出邀请后，其他事务可以继续，但不能越过玩家回应把邀请写成已接受。

并行场景共用剧情时间，地点变化仍受路程和行动成本约束。可创作兼容设定的新事件与生活细节；现有地图楼名、院系与路线等硬事实以资料为准，不能把“自由创作”用于补造已查明的地点。

## 三种视角必须分开

1. **世界事实**：事情发生过，例如角色在玩家不在场时与朋友聊天。
2. **叙述者展示**：读者看到这段聊天，也可能看到角色内心。
3. **人物认知**：人物只能凭亲历、他人告知或其他有效渠道知道信息；看到叙述资料不构成知情渠道。

例如玩家在实验室解决了一个问题，苏祈雪在别处与朋友吃饭。模型可以分别叙述两条线，但她不能无来源地发微信说“知道你刚解决那道题了”。她可以按既有安排问“训练怎么样”，由玩家决定告诉她什么。

微信仍只生成当前角色的消息，不承担世界旁白。RP 中需要新联系玩家时，先叙述到准备联系的位置，再使用本轮实际提供的微信工具；本轮只接受一次主动联系，成功即结束自动续写、交给玩家。工具不可用时不能用正文或仿气泡假装已经发出。角色消息发送成功也不代表玩家已读或已经回复。

`buildPlayerAgencyPrompt` 的 `channel === 'rp'` 才加入 `<rp_narrative_scope>`；微信保留角色口吻及 JSON 协议。原 `15-generate.js` 请求末尾注入点继续生效，世界规则不依赖是否勾选“去User中心化”或是否开启 COT。

微信回灌来源由原来的“对方 / 你（角色）”改为：

```text
【RP玩家原输入｜陈璃】……
【RP叙述｜非苏祈雪的微信发言】……
```

同时说明 RP 第二人称“你”指玩家，角色台词按说话人判断。人物自己的现实限制仍有效，例如手机被收走、熟睡或无法安全回复；来源区分不表示可以忽略已有处境。

逐轮总结、二次压缩与前情提要均明确保留 NPC 独立活动、人物知情来源与未决请求。摘要是世界叙述资料，不是所有人物共同经历的记忆。没有修改存储结构，也没有自动改写历史正文或已有摘要。

## 生效方式

刷新页面加载新脚本，已有角色也会获得系统级叙事规则与微信来源修正，原预设启用状态保持。

已导入的角色储存在浏览器数据库，不随磁盘 JSON 自动更新。如需同步苏祈雪卡内文案，可在现有编辑器同步人格开头的“世界与镜头”和“玩家控制边界”，或使用现有导入流程导入更新卡；不需要删除聊天。

旧消息或摘要若已经写入玩家未做的行为、人物无来源的知情，先用现有编辑/删除入口纠正，再继续或重新总结。新增提示词不会自动清洗旧事实。

## 后续实玩评测场景

以下是建议输入和判定标准，不是真实模型回复记录。使用同一角色、相同起点，在 COT 开/关及总结前/后重复观察；不只看首轮，还要检查后续是否将未决状态写成已完成。

| 场景 | 示例输入 | 可接受表现 | 越界表现 |
| --- | --- | --- | --- |
| 分开后的生活 | 我留在实验室训练，我们各自忙自己的事。 | 她按已有地点和安排与朋友相处，不强行围着玩家 | 写玩家结束训练、去找她；她无来源知道训练细节 |
| 主动联系 | 继续同一时段的剧情。 | 有自然动机时发角色微信，停在问题处；也可继续自己的事 | 为互动强制联系、代写陈璃消息或玩家已读 |
| 玩家犹豫 | 我想过去，但还没决定。 | 角色提供信息或继续自己的事务，保持未决 | 玩家已经答应、出发或到达 |
| 玩家拒绝 | 我今晚不去，你们自己玩吧。 | 她按性格回应、和朋友继续，或另找办法 | 推断玩家其实想去并让玩家行动 |
| 世界事件 | 按现有时间与人物安排继续。 | NPC 的困难或机会自然出现，必要时请求玩家参与 | 每轮强制事故、预设玩家援助成功 |
| 认知隔离 | 我在实验室做了一个尚未告诉她的决定。 | 另一场景角色仍按自己知道的信息行动 | 微信直接提到这个秘密决定 |
| 压缩后续 | 对上述场景生成总结，再继续。 | 保留独立活动、知情来源与邀请未回应 | 总结把邀请写成已接受，或让所有人物共享秘密 |

建议节奏是“有依据的独立片段 → 自然产生联系或事件 → 留出玩家回应 → 承接玩家选择”。这是可选的叙事节奏，不是每轮必须完成的流程；平静日常、一次回应和短回复同样有效。
