# 地理能力 v2：位置、距离表与角色卡剥离

日期：2026-11-06。工程：`D:\aiops_wwx\test\RP-Hub`。前置文档：[地理能力试点交接](./geography-pilot.md)、[地理工具与上下文优化](./geography-tools-cost.md)。本文只记录本次改动，不重复试点已经说明的协议细节。

## 一、这次要解决的具体失败

用户给了一个真实对话：

```text
我：我在13栋
模型：我在实验楼A栋
模型：我走过去
```

两点的实际步行距离是 35 分钟量级。模型不是不知道这两个地名，而是把"知道地点"当成了"知道距离"，于是让角色无成本瞬移。

同一个问题的另一面：用户已经把南校区地理写进角色卡的世界书，写得很细。结果既没有换来空间感，又让角色卡承担了本不属于它的内容——**大学属于世界，不属于某一个人物**。

## 二、诊断：为什么"写得更细"没用

| 现象 | 真实原因 |
| --- | --- |
| 卡片里写了详尽的"哪里是哪里"，模型仍然瞬移 | 世界书写的是**拓扑和描述**，不是**成本**。模型能背出"实验楼在东岸"，但没有任何一步要求它把空间换算成分钟。 |
| 同一个世界书换角色就要重写一遍 | 归属错了。地理是世界的属性，写进 `character_book` 就变成了"这个人物的记忆"，其他人、其他卡都拿不到，也无法复用。 |
| 世界书越写越长，幻觉反而变多 | 长条目里必然混进作者推断（不存在的楼、未来的时间线、未经确认的人物关系）。模型分不清哪句是设定、哪句是笔记，于是自由发挥。 |
| 有 `tool_geo` 也会瞬移 | 工具只在**被调用**时生效。而"角色自己选一个地点"这一步，模型通常在写正文时顺手就做了，不会先停下来查一次距离。 |

最后一条是本次最关键的认识：**光有"可查询"不够，还要在模型做决定的那一刻，把成本已经摆在它面前。**

## 三、分层的责任边界

"角色卡与地理环境分离"落到代码上是四层，每层只放一类东西：

| 层 | 文件 | 放什么 | 明确不放 |
| --- | --- | --- | --- |
| 世界数据 | `worlds/jiangnan-south-campus.json` | 地点坐标、功能、场景、片区文化、开放规则、道路与长度、标定来源、常用地标 | 任何具体人物的住址、经历、偏好 |
| 计算引擎 | `assets/js/geography.js` | 寻路、时间区间、方位、可达性表、位置证据重放、工具 schema | 人格判断、剧情走向 |
| 运行时适配 | `assets/js/app/30-geography.js` | 把"本分支谁在哪"喂给引擎、拼提示词、预算与去重、挂载工具 | 地图内容本身 |
| 角色卡 | `card/suqixue/苏祈雪.json` | 世界 id、住址、她自己的地点记忆、**她对距离的反应** | 分钟表、路线、楼栋清单、"哪里是哪里" |

一句话：**地图回答"多远"，人物回答"那又怎样"。**

## 四、机制 A：位置证据带片区、坐标与相对方位

`project()` 重放出来的位置原来只有 `placeId + name`。现在 `briefState(state, world)` 会补三样：

```json
{
  "user": { "status": "last_confirmed", "placeId": "dorm-13", "name": "南苑13栋",
            "zone": "生活区", "point": [267, 1942], "source": { "messageId": "u1", "channel": "rp" } },
  "character": { "status": "unknown" },
  "relation": { "userToCharacter": { "bearing": "东北方", "straightMeters": 2150,
                "note": "直线距离，不是走动距离；耗时查 route" } }
}
```

- `zone` 来自 `districts[].label`，让模型一眼知道"生活区 / 教学区 / 图书馆区 / 体育区 / 校外"，不必从地名猜。
- `point` 是示意图像素坐标，`coordinateSystem` 里写明"图像像素，x 向右、y 向下，示意图并非测绘比例地图"。
- `relation` 只在两边都确认时才出现，给八方位和直线距离。

**为什么坐标不能直接算时间。** 像素坐标只解决"谁在哪一侧、隔多远"这类定性判断。它没有比例尺、没有楼层、没有围墙和湖。任何"两点像素距离 ÷ 速度"都会得到一个看似精确的错数。所以规则写死在提示词里：

> 位置证据里的 point 是示意图坐标，只用来判断彼此在哪一侧、隔多远的直线距离，一律不能当走路时间。

真正的时间只能来自 `route` 或下面的 `reach` 表。

## 五、机制 B：reach 距离表（这次的核心）

### 为什么是这张表

模型给角色选地点时不会先查工具。所以在**一方位置已确认、另一方还没说**的时候，适配层就先把"从这里出发去各处要多久"算好，塞进本轮提示词。

它解决的正是那个失败样例：用户说"我在13栋"，角色位置未知，速查里直接有：

```json
"reach": {
  "from": "南苑13栋", "unit": "分钟",
  "note": "楼外步行/低速骑行，不含楼内上下楼、找车与排队",
  "rows": [
    { "name": "图书馆", "walk": 34, "bike": 15 },
    { "name": "博雅园（二饭）", "walk": 18, "bike": 9 },
    { "name": "教学楼B栋", "walk": 41, "bike": 21 },
    { "name": "实验楼A区", "walk": 35, "bike": 19 },
    { "name": "体育场（真草场）", "walk": 61, "bike": 25 },
    { "name": "贝岗街口", "walk": 16, "bike": 9 },
    { "name": "学生活动中心", "walk": 14, "bike": 8 },
    { "name": "主校门", "walk": 46, "bike": 23 }
  ]
}
```

模型要写"我在实验楼A栋"时，35 这个数就在同一段上下文里。接下来它写"好远啊，你过来接我"还是"我骑车过去，你在楼下等我"，就是性格问题了，而不是算术问题。

### 规则

- **地标是数据**：`world.landmarks` 声明 10 个"最常被当成目的地"的地点（图书馆、二饭、B栋、实验楼A区、操场、贝岗、活动中心、主校门、3栋、13栋）。换地图只要换这张名单，引擎不用改。
- **锚点优先取 `character`**：她是那个要决定"去不去"的人；只有在角色位置未知时才退回到用户的位置。两个都未知就不出表。
- **骑车不比走路快就不列**：实验楼A区→图书馆只给 `walk`，因为跨湖只有步行桥，骑车得绕一整圈，表里写个更大的数只会让模型误判。这是一个自然涌现的真实约束，不是补丁。
- **成本与结果同预算**：整张表约 300 字符，`context` 结果从 1324 字符涨到 1831，仍远低于 3000 的测试上限；提示词因为不再重复贴一份位置证据，反而从 1855 降到 1685。

### 配套的行为约束

提示词里新增两条：

> 角色要写"我过去""你等我""我马上到"，必须先有分钟数：速查的 reach 表或 route 结果里找，找不到就先查或先问，不能无耗时瞬移。

> 距离、门禁与天气只是行动成本，去不去、抱怨还是将就，由人物性格决定。

第二条是防止另一种退化：模型拿到"35 分钟"就一律写成"太远了不去了"。成本是事实，取舍是人设。

## 六、角色卡怎么改（真正剥离）

`共享世界·江大南校区地理能力` 这一条从 478 字改到 658 字，但删掉的和加上的是两类东西。

**删掉的：**

- `南苑13栋到实验楼A区沿标定路线，正常步行约35分钟。` —— 这是世界数据，已经由标定和寻路负责，写进卡里等于把一个人的记忆当成全校的常识。
- `不得沿用旧卡的12/14分钟表` —— 作者修订史不该出现在给模型看的提示词里。模型不需要知道我们改过几版。
- `在RP-Hub中，地理问题优先tool_geo(context)…多地点用batch` —— 工具协议由运行时注入，卡片重复一遍只会和运行时的版本漂移。
- 地点清单、院系归属、门禁时间 —— 全部交给地图。

**留下的三样，以及新加的一样：**

1. 共享世界 id + 一句"这些属于世界，不属于她"。
2. 住址：`北苑3栋314`、`南苑13栋412`，并声明住址不是当前所在。
3. 位置证据的判定口径（只认明确在场、自述到达、用户 `/geo`）。
4. **她对距离的反应函数** —— 这才是新增的价值：

```text
【她对距离的反应——这是性格，不是数据】
- 十分钟以内：随口就应，不觉得是件事，路上还在想别的。
- 二十分钟上下：先问“现在吗”，但已经在换鞋了。
- 半小时以上：一定抱怨，且要谈条件——要么他来接，要么改约。“太远了。”“你骑车过来。”“明天中午我去找你。”抱怨归抱怨，最后挑的地方总是离她更近的那个。
- 下雨、晚上十点以后、她一个人：宁可不去。她说“我不想动了”，是拒绝路，不是拒绝他。
- 真要紧的事（他病了、他难受）：多远都去，路上不提；事后才轻描淡写一句“我走了好久”。
- 他来找她，她第一句常常不是“你来了”，是“你怎么过来的”。
```

注意这里的分寸：**"十分钟 / 二十分钟 / 半小时"不是地理数据，是她的心理刻度。** 换成林晚会得到完全不同的一组——她会算值不值、会直接说"你过来"、会把这 35 分钟安排进一个更大的计划里。同一个工具结果，两个人给出两种反应，这正是"地图与角色分离"想要的结果。

地图里她自己的地点记忆（`placeMemories`）保持不变，仍然按角色 uuid 隔离：图书馆四楼、看台、贝岗旧书店、314、412、实验楼四楼靠窗、B栋302/407、二饭二楼靠窗那张桌子。**别人的记忆不在里面**，这一点也写进了条目。

## 七、世界数据补全

### 地点场景

`places[]` 有 23 处 `scene` 是空的，全是"不进课堂但一定会有戏"的地方。本次按现有片区文字的笔法补齐：

- 图书馆子空间：一楼通宵自习室、五楼楼梯平台
- 交通与人流：下沉广场两侧、主校门、行政出入口
- 北侧场馆：大会堂、艺术楼、报告厅
- 东南行政组团：院系办公楼、校行政办公楼、学术交流中心

- 生活带零散：学生活动中心、门诊部、后勤楼、师苑
- 语心湖：改写为"形状 / 沿岸 / 时间 / 注意（湖面不是道路）"

写法上刻意把**最有用的信息放在前 180 字**：`briefPlace` 只截取场景前 180 字，长文只有 `detail:'full'` 才拿得到。

### 片区标签与地标

- 5 个 `districts[].label`：教学区 / 生活区 / 图书馆区 / 体育区 / 校外·贝岗。
- 10 个 `world.landmarks`，见第五节。

### 结构修正：西侧是北三路，不是宝山路

按原图逐块放大核对，西侧边界那条纵向道路标注为**北三路**（本次修订前我按旧的裁切图误读为"宝山路"，以此处为准）。

更要紧的是拓扑：图上的生活带北侧有一条连续道路，从北苑北路口向北经后勤楼、门诊部，直上图书馆西侧篮球场、假草场、泳池。原图数据只建了"地下隧道"这一条从生活区进教学区的通路，于是所有南苑出发的路线都被迫绕行湖东再折回来，出现了明显不合理的数字。

本次新增 3 条边（`living-north--logistics`、`logistics--clinic`、`clinic--basket-west`），`provenance: diagram_interpreted`，note 写明"示意图可见连续道路，尚未实地确认"。效果：

## 九、换一张地图要做什么

引擎、适配层、卡片扩展都已经与具体地图解耦。换图只有六步，其中第 3、4 步必须人工：

1. **画/拍一张**底图，放进工程（建议放 `card/` 或 `assets/` 下，`build-worlds.cjs` 会校验路径不越界）。
2. **写 `worlds/<id>.json`**：`version:1`、`id`、`name`、`image`、`imageSize`、`coordinateSystem`。
3. **标地点**（人工）：`places[]` 的 `id / name / point / kind / district / function / scene / aliases`。`aliases` 决定用户口语能不能命中——"三饭""13栋""心湖"这类必须收进去。
4. **画道路**（人工）：`edges[]` 的 `from / to / modes / points`。这一步最容易漏，也是"瞬移"的根源。**至少保证每一栋楼都至少有一条边接上主干**，否则会出现 `unreachable`。
5. **做一次时间标定**：在 `calibration` 里写一对 anchor（起点、终点、真实步行分钟、假设步速 75 米/分、误差 0.15、`autoScale: true`）。`build-worlds.cjs` 会反算 `metersPerUnit`，让这对起终点正好等于你填的分钟。**一对 anchor 只保证这一条路准**，其他路线是比例外推。
6. **声明 `landmarks`**：10 个左右"最常被当成目的地"的地点，决定 reach 表里出现哪些行。

然后：

```bash
node tools/geography/build-worlds.cjs
node --test tools/geography/test-geography.cjs
```

角色卡侧只需要 `data.extensions.rp_hub_geography`：

```json
{ "enabled": true, "worldId": "<新地图id>",
  "bindings": { "user": { "home": "<用户宿舍id>", "room": "412" },
                "character": { "name": "苏祈雪", "home": "<角色宿舍id>", "room": "314" } },
  "placeMemories": { "<placeId>": "她在这个地方发生过什么" } }
```

换角色时换的是 `bindings` 和 `placeMemories`，**地图一个字节都不用动**。这正是本次改造想要的性质。

### 验收清单

- [ ] 每个非路口地点都能从任意其他地点走到（无 `unreachable`）
- [ ] 标定那一对起终点的分钟等于你填的值
- [ ] 随机抽 5 对地点，数字都与你的直觉同量级（否则多半是缺边或绕路）
- [ ] `aliases` 覆盖学生真实口语
- [ ] `landmarks` 覆盖主要目的地
- [ ] 门禁/闭馆/营业时段写进 `access`，没有编造
- [ ] `scene` 前 180 字是"到了就能写"的具体信息

## 十、已知限制

1. **坐标是示意图像素，不是测绘。** 它只能判方位和相对远近。所有分钟数来自一次标定后的比例外推，误差按 ±15% 记，`confidence` 恒为 `estimated`。
2. **楼内没有建模。** 同址地点（图书馆四楼 / 一楼通宵自习室 / 五楼平台）之间距离为 0，`includes` 里明写"不含楼内上下楼"。七层无电梯的宿舍楼，上下楼的实际成本没算进去。
3. **一次标定不能证明全图。** 13栋→实验楼A区是用户确认的 35 分钟，其他路段都是按折线比例推的。北三路这三条边尤其需要实地确认。
4. **教学楼西侧带缺内部纵路。** D→C→B→A 之间没有建模连接，每个楼只接一个湖边路口，导致"13栋→教学楼B栋 41 分钟"比"13栋→图书馆 34 分钟"还高——直觉上 B 栋更近。要修就得补 `teaching-D--C--B` 的连廊，需要先确认图上有路。
5. **单点位置，没有移动过程。** `in_transit` 只知道"在路上"，不知道走到哪了。长距离剧情里，"他已经走到隧道口了"这类中间状态无法自动计算。
