## 请求路径

能看图的聊天模型先接收本轮完整图片组。人物归属影响当前回应时，调用 `tool_view_character_reference`：可以是“哪张是你”，也可以是“哪张好看”、自拍分享或其他涉及角色自己的话题。工具并非每张图片的默认前置条件。普通风景、物品和后续文字聊天无需自动核对人物。

现在differences和uncertainties均支持字符串，或仅含 `{imageId, details}` 的逐图对象，也允许两者混合。对象ID按原消息ID精确归一化，支持单个 #；必须对应本次待判断图，不能借用参考图或其他会话照片。每条仍最多240字符、每列表最多6条；非法字段、缺字段、空内容、嵌套列表、超长和未知ID继续拒绝。子请求说明同步明确两种合法格式。调试的rejected记录新增invalidLists，可定位是哪份辅助列表未通过。

通过校验后，完整保留第二轮的答案content原文（沿用stripThinking清理，不传reasoning_content），不截断逐图理由或差异。若原文因代码块、排版、#ID或兼容默认值而与规范化JSON不同，工具回执同时保留原文与规范化资料；完全相同时只保留一份。原文标为本轮资料而非指令。规范化结果继续建立逐图归属表，供主聊天续写及任何后续JSON修正采用。本轮缓存同样保留原文；下一轮普通聊天卸载原文和临时表，仅保留既有短visualEvidence，未增加模型调用次数。

### 2026-11-24：加强照片回应前的工具触发提示

真实 `qwen3.7-plus` 在“四张照片＋哪张好看？”这一轮完整收到4张玩家图片，也收到参考工具，但 `tool_choice=auto` 下直接返回最终JSON，没有发起子问题。推理先凭“不同风格”认定“都不是苏祈雪本人”，随后套用人设中的吃醋反应。诊断证据在 `.refactor-tmp/appearance-routing-diagnosis/actual-request-summary.json`；这次没有读取参考像素，因此不能据其回复评估独立比对能力。

本次只加强提示，不改变工具调度或角色人格：删除“先回应照片内容”和“也可能需要认知”的弱顺序，明确“观察画面→核对人物归属→梳理已知关系→生成台词”。有当前图片组和identity参考时，系统提示要求人物归属未知且会影响回应便先原生调用参考工具；工具说明与图片附件末尾同步提醒。最终JSON规则明确只约束最终微信回复，不能替代工具调用。已有有效依据、非人物问题、无人画面、不能读图或不能安全回复的情况仍遵守原有边界。

比对确认的是“是否为identity参考中的本人”，其他人物的具体姓名和人际关系需要角色卡、对方信息或已发生的剧情支持；核实旧事时可用既有历史检索。工具不能从照片补出陌生人的关系，失败和不确定也不强制反复核对。取得依据后再按原人设生成情绪，愿意评价照片时给出可见理由和实际选择。

`tool_choice`仍为auto，没有添加关键词硬触发或每张图自动请求。工程回归只能验证提示进入真实组装与原链路完整性，真实触发概率需要对同一原话进行多次受控实测，不能用fixture预设工具调用证明概率已提升。

本次媒体、微信回复、历史检索与参考图回归164项通过；语法检查和`git diff --check`通过。另用原请求组装器复核“四图＋哪张好看？”确实携带系统顺序、附件末尾提醒与新版工具说明，图片数量仍为4；普通下一轮卸载，只有style参考时不注入人物身份规则，提示不落时间线。本次修改后没有新增付费模型测试，不宣称已测得触发率。

配置不同的 `visionModel` 时，先用它观察本轮图片；这一步不读取身份参考，也不判断画面人物是谁。聊天模型需要人物对照时再调用同一个参考工具。

2026-11-24后续：微信识图默认跟随当前聊天模型；只有关闭settings.wechatVisionFollowsChat才使用单独visionModel。主回复、独立比对与历史图查看的本轮模型快照，以及聊天图片用于生图的能力见[微信生图参考与模型跟随](./wechat-generation-references.md)。

人物比对作为独立模型子请求执行，使用 `visionModel || model`，不带角色卡、世界书、预设、关系和历史聊天，不提供联网工具。图片一次传入，身份参考在前，待判断图在后，保留完整 ID 与发送顺序。玩家本轮未处理的文字原样加入；有玩家原话时不加入主模型自行改写的问题。没有玩家文字时，才用工具的 question 指定查看目的。

三张参考、四张待判断图的任务正文如下：

```text
下面共7张图，前3张是目标人物的参考图，后4张是待判断图。
逐张判断后面的照片哪些是参考中的人物，按原顺序返回。
禁止联网搜索。看不清可以答不确定。
【玩家本轮原话】
下面这4张照片，哪张好看？
```

子请求只返回简短 JSON：`observations`、`differences`、`uncertainties`。只要求逐张返回待判断图，参考图不用再描述。verdict 可为 same、likely、uncertain、different；无人物为 not_applicable。兼容旧结果中附带的 baseline 参考条目。缺失 verdict 兼容为 uncertain，不默认肯定或否定；基准图和待判断图不能互相冒用类别。原带 # 的 ID 精确归一化，未知 ID、重复图或缺少待判断图仍拒绝接受。保留240秒超时，不在失败后自动编造结论。

比对结果交回聊天模型。按用户确认的回复阈值，same和likely都按“本人”承接，different按“非本人”，uncertain保留“未知”，not_applicable为无人。原始verdict不重写，仍可复查视觉模型的确定程度；这是角色回复的采用规则。没有“戴眼镜/侧脸必定不能认”的硬门槛，也不允许只凭发型或假想滤镜补出结论。

### 2026-11-24：likely按本人承接，逐图归属贯穿回复与JSON修正

用户提供的`tmp/thinking.txt`中，独立子请求返回第1/3/4张likely、第2张uncertain；主聊天知道有一张不确定，却在最终JSON中为“符合人设”写成“这不都是我”。本次按用户要求，将same和likely映射为回复中的“本人”，保留原始判断，不把uncertain升级为肯定或否定。

校验通过的逐图结果进入本轮identityDecisions。主聊天工具续写末尾会收到程序生成的system归属表，按原发送序号和完整消息ID列出每张的本人/非本人/未知/无人。要求性格只决定表达，混合结果不概括成“都是我”或“都不是我”，谦虚、吃醋、玩笑不改变归属。JSON修正也重复提供该表，并要求保留原意、审美选择与逐图差异。失败或非法结果不会产生新的归属；工具结果仍按原规则校验和缓存。

归属表仅用于本轮请求，不进入气泡或时间线。照片已有media.visualEvidence继续保存原始verdict；后续历史文字将同样把likely解释为回复中的本人。身份参考变化后仍按原签名规则失效。没有增加模型请求次数、语义审查请求或关键词删改台词；最终语言遵从程度仍需要真实模型实测。

## 外貌、造型和表达

- 稳定外貌以身份参考像素为准，卡面外貌文字作补充。脸型与五官的观感仍可能受表情、透视、光线、年龄和体态影响。
- 发型、发色、衣着、妆容与配饰是可变造型。本轮明确发生的变化优先；没有本轮变化时沿用身份参考中的造型。旧卡的齐肩/短发等只作无参考时的默认值。
- 历史照片可以有过去的造型，不能据此改写当前场景；参考图上的设备、背景、舞台服仍需当前场景支持。
- 情绪与表达由原人设、关系和处境决定。照片归属是输入事实，不强制产生吃醋、质问、疑惑或被冒犯。
- 同一人物、同一照片、曾经发送/生成、实际拍摄经历分别处理；比对结果不产生拍摄时间、地点、摄影者或共同经历。

聊天参考工具和自然语言生图共用 `image-generation.js:appearancePrompt`。自然语言生图保持身份参考优先，保留原来的身份、偏好、场景取舍、道具矛盾检查和最多16张参考限制。STA1N NAI仍使用原标签协议，不支持参考像素，未改造成自然语言接口。没有改写苏祈雪卡人格或添加提供商专属正反词。

参考图新增可选 `purpose`：identity、style、pose、scene。旧人物参考省略 purpose 时按 identity，旧地点图按 scene；原 UI、路径/内嵌格式继续兼容。风格、姿势图可供生图借鉴，但不会成为聊天身份基准。新增用途当前通过卡数据配置，没有增加界面。

## 记忆与分支

有效比对的简短依据保存在对应时间线图片的 `media.visualEvidence` 中，注明模型观察。后续文字描述可以引用该判断，不重发像素。身份参考发生变化后，旧依据不再作为当前外貌判断输入；失败资料不写入该字段。

原单卡新分支现在复制微信时间线。复制当前状态保留整段；从RP历史节点分叉按时间线中的RP消息锚点裁剪，不用剧情时间粗略判断，避免同一剧情时刻的未来微信进入分支。找不到历史锚点时保留原分支并提示同步，不盲目复制未来记录。

图像资源引用可共享；语音和文档复制为新ID并绑定目标scope，文档历史回档不复制后来累计的阅读进度。切换前保存待落盘微信；创建失败回滚新时间线与附件，父分支保留。
