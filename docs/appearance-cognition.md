# 角色外貌认知与按需视觉比对

更新：2026-11-24。本文件描述当前实现；此前关于无条件独立身份核对、齐肩设定优先和 likely 一律视为看不清的记录属于历史版本。

## 请求路径

能看图的聊天模型先接收本轮完整图片组。人物归属影响当前回应时，调用 `tool_view_character_reference`：可以是“哪张是你”，也可以是“哪张好看”、自拍分享或其他涉及角色自己的话题。工具并非每张图片的默认前置条件。普通风景、物品和后续文字聊天无需自动核对人物。

配置不同的 `visionModel` 时，先用它观察本轮图片；这一步不读取身份参考，也不判断画面人物是谁。聊天模型需要人物对照时再调用同一个参考工具。

人物比对作为独立模型子请求执行，使用 `visionModel || model`，不带角色卡、世界书、预设、关系和历史聊天，不提供联网工具。图片一次传入，身份参考在前，待判断图在后，保留完整 ID 与发送顺序。玩家本轮未处理的文字原样加入；有玩家原话时不加入主模型自行改写的问题。没有玩家文字时，才用工具的 question 指定查看目的。

三张参考、四张待判断图的任务正文如下：

```text
下面共7张图，前3张是目标人物的参考图，后4张是待判断图。
逐张判断后面的照片哪些是参考中的人物，按原顺序返回。
禁止联网搜索。看不清可以答不确定。
【玩家本轮原话】
下面这4张照片，哪张好看？
```

子请求只返回简短 JSON：`observations`、`differences`、`uncertainties`。只要求逐张返回待判断图，参考图不用再描述。verdict 可为 same、likely、uncertain、different；无人物为 not_applicable。兼容旧结果中附带的 baseline 参考条目。缺失 verdict 兼容为 uncertain，不默认肯定或否定；基准图和待判断图不能互相冒用类别。原带 # 的 ID 精确归一化，未知 ID、重复图或缺少待判断图仍拒绝接受。保留240秒超时，不在失败后自动编造结论。

比对结果交回聊天模型。same 支持认出本人；likely 保留倾向但不确定；different 支持不同；uncertain 保留未知。没有“戴眼镜/侧脸必定不能认”的硬门槛，也不允许只凭发型或假想滤镜补出结论。

## 外貌、造型和表达

- 稳定外貌以身份参考像素为准，卡面外貌文字作补充。脸型与五官的观感仍可能受表情、透视、光线、年龄和体态影响。
- 发型、发色、衣着、妆容与配饰是可变造型。本轮明确发生的变化优先；没有本轮变化时沿用身份参考中的造型。旧卡的齐肩/短发等只作无参考时的默认值。
- 历史照片可以有过去的造型，不能据此改写当前场景；参考图上的设备、背景、舞台服仍需当前场景支持。
- 情绪与表达由原人设、关系和处境决定。照片归属是输入事实，不强制产生吃醋、质问、疑惑或被冒犯。
- 同一人物、同一照片、曾经发送/生成、实际拍摄经历分别处理；比对结果不产生拍摄时间、地点、摄影者或共同经历。

聊天参考工具和自然语言生图共用 `image-generation.js:appearancePrompt`。自然语言生图保持身份参考优先，保留原来的身份、偏好、场景取舍、道具矛盾检查和最多16张参考限制。STA1N NAI仍使用原标签协议，不支持参考像素，未改造成自然语言接口。没有改写苏祈雪卡人格或添加提供商专属正反词。

参考图新增可选 `purpose`：identity、style、pose、scene。旧人物参考省略 purpose 时按 identity，旧地点图按 scene；原 UI、路径/内嵌格式继续兼容。风格、姿势图可供生图借鉴，但不会成为聊天身份基准。新增用途当前通过卡数据配置，没有增加界面。

## 记忆与分支

有效比对的简短依据保存在对应时间线图片的 `media.visualEvidence` 中，注明模型观察。后续文字描述可以引用该判断，不重发像素。身份参考发生变化后，旧依据不再作为当前外貌判断输入；失败资料不写入该字段。

原单卡新分支现在复制微信时间线。复制当前状态保留整段；从RP历史节点分叉按时间线中的RP消息锚点裁剪，不用剧情时间粗略判断，避免同一剧情时刻的未来微信进入分支。找不到历史锚点时保留原分支并提示同步，不盲目复制未来记录。

图像资源引用可共享；语音和文档复制为新ID并绑定目标scope，文档历史回档不复制后来累计的阅读进度。切换前保存待落盘微信；创建失败回滚新时间线与附件，父分支保留。

浏览器用独立来源/IndexedDB和本地模拟接口运行13项检查。真实Canvas读取三张参考与四张测试图，实际请求图片数为 `4 → 7 → 4`：主聊天、独立比对、主聊天续写。下一轮为单请求、零图片。报告在 `.refactor-tmp/wechat-reference-check/report.json`，截图为同目录 `browser-check.jpg`。

以上证明工程组装与状态行为，不代表真实模型已达到4/4辨别率；没有调用付费模型或生图服务。后续实测可比较同一模型、同一图片、同一原话的独立子请求与角色聊天结果，分别评估误认、漏认、不确定和关系表达。
