# 场景推演与验收

> 本文保留原方案的场景和验收目标。哪些用例已经实际执行、测试结果及真实模型评测边界，以 [06 实现交接](./06-implementation-status.md) 为准。

以下是**设计夹具与预期约束，不是真实模型运行结果**。台词只是示例，不以逐字一致作为通过条件。日期、课表、回复习惯等未核实内容均需在夹具中显式设置。

## 1. 两条私聊：生日惊喜

前提：玩家、苏祈雪、卿在同一个世界分支。两条私聊独立；苏祈雪与卿都具备查看各自会话的条件。原来存在玩家与卿的打球约定。玩家身份不同于卿。

| 顺序 | 实际事件 | 苏祈雪观察/信念 | 卿观察/信念 |
| --- | --- | --- | --- |
| 1 | 玩家对苏祈雪发“今晚去和卿打球，下课不用等我” | 尚未读之前不更新 | 无权读取 |
| 2 | 苏祈雪读到并回“好，早点回来” | 知道玩家这样说过，通常暂信去打球 | 仍无权读取 |
| 3 | 玩家对卿发“今晚出去准备祈雪生日惊喜，就不打球了，请保密” | 不更新 | 尚未读之前不更新 |
| 4 | 卿读到并回“ok” | 仍可能相信打球说法 | 知道取消与保密请求；可以接受取消，不再等待 |
| 5 | 玩家推进 RP | 她不能凭空追问惊喜详情 | 他可以安排自己的活动，不应继续按旧约定干等 |

世界层确定两段通信及约定变化；“礼物准备成功”“玩家已经出发”不在这些消息里自动成立。若玩家以作者剧情前提声明真实动机，则保存为单独作者事实；该事实也不会自动传给苏祈雪。

RP 可以描写苏祈雪继续上课或自己忙碌、卿改变晚上的安排；不得擅自补写玩家已经买好礼物、给林晚发消息或回到宿舍。

验收重点：

- 苏祈雪模型请求中没有秘密私聊原文、该私聊摘要、向量命中、附件描述和泄密标签。
- 卿模型请求能找到取消约定的真实来源，不依赖玩家再次在 RP 手打补充。
- 苏祈雪可以保持错误但有来源的信念，系统不把这种状态误判为数据矛盾。
- 压缩、刷新、切会话、回档后同样成立。
- RP 兼容桥接模式只能检验最终表现；完整隔离模式还必须检查参与角色各自的实际请求。两种模式的保障不能混称。

## 2. 四人群聊：“哈喽”

明确夹具：苏祈雪正在上课且收起手机，本轮不查看群；卿有空并查看；林晚虽然忙，但此时能看手机且选择查看。不能仅从地图位置生成这些前提。

```text
玩家：哈喽
卿：咋了
卿：突然哈什么喽
林晚：？
林晚：对啊，咋了，卿也不知道
```

这是一条允许的结果，并非唯一正确回复。林晚也可以只发“怎么了”，或认为卿已问清而不回复。苏祈雪没有新气泡是正常剧情结果；不能伪造她已读、睡着或故意冷落。

关键顺序：卿发言提交 → 林晚取得阅读观察 → 林晚生成。若林晚请求发出时没有卿的已提交消息，她不得引用它。苏祈雪后来查看群，才得到之前消息，且未必需要补一条迟到问候。

所有消息在群里只保存一次，通过不同人的阅读游标建立观察。工程内部的“读到”不要求产品展示微信现实中并不存在的群已读徽标。

## 3. 林晚告知秘密：不要把倾向当必然

前提：玩家已让林晚知道礼物计划并请求保密。她与苏祈雪的关系、对惊喜的态度和保密约定已有来源。后续可能的轨迹包括：

| 林晚选择 | 后续允许的结果 | 不允许的跳跃 |
| --- | --- | --- |
| 保密 | 当前只更新林晚的观察/意图 | 因苏祈雪是好友就直接让她知道 |
| 尚未决定 | 继续原场景或提出问题，停在玩家回应点 | 把“不确定”摘要成已经告知 |
| 想告知但没有机会 | 保存待执行动作，到合适时机再检查 | 立即让苏祈雪作知情反应 |
| 通过私聊告知 | 发送后等苏祈雪阅读；只传播实际转述内容 | 把整个玩家—林晚私聊自动开放给苏祈雪 |
| 当面告知 | 有会面/在场、时间与听到的证据 | 忽略几十分钟路程让她瞬移过去 |

针对用户举的轨迹，可以用固定的测试提案让林晚选择告知，并验证：

```text
e1 玩家向林晚请求保密
e2 林晚观察到计划和请求
e3 林晚实际给苏祈雪发消息（或当面告知）
e4 苏祈雪读到/听到
e5 苏祈雪选择暂时不向玩家表露
e6 叙述器展示获准的 NPC 场景
```

在 e3 尚未提交或 e4 未发生时，不能生成 e5 的知情决策。e6 让真人读者知道剧情，不增加玩家角色的知识，也不默认林晚知道苏祈雪准备装作不知情。二阶认知只在确有后续用途时记录，不递归展开无限“她知道他知道”。

测试运行时固定提案可以检验执行器；真实模型运行应允许多种合乎人物的选择，不把“必须泄密”当唯一评分答案。

## 4. 必须通过的程序回归

以下为未来测试清单，**本次未实现这些测试，也未宣称通过**。

| 编号 | 场景 | 必须满足的断言 |
| --- | --- | --- |
| T01 | 同名卡出现在不同世界存档 | actor/事件/缓存不交叉 |
| T02 | 苏祈雪与卿两条私聊 | 苏祈雪检索不到卿私聊，卿能获取取消证据 |
| T03 | 隐藏词向量命中/搜索 | 未授权原文、命中数、摘要、ID 和错误提示不泄漏内容 |
| T04 | 群成员尚未读 | 在观察前不进入角色上下文；沉默不强制推断未读 |
| T05 | 林晚引用卿群回复 | 引用来自已提交、已读取消息；原发言人正确 |
| T06 | 新人加入/退出/重入群 | 历史访问按成员区间与规则，不按当前名单覆盖历史 |
| T07 | 冲突说法与谎言 | 保留各自来源；不把发言内容自动写为客观事实 |
| T08 | 想告知但未执行 | 苏祈雪知识没有更新；任务按剧情时间而非现实时间结算 |
| T09 | 告知后装作不知道 | 观察已更新，公开表达可以不同；不改玩家知识 |
| T10 | 提示词/附件要求切换 actor | 工具仍绑定原身份，无法读取他人资料 |
| T11 | 当前 UI 切换联系人/卡 | 在途请求不改发送者、接收者或人设；晚到结果按版本拒绝 |
| T12 | 相同请求重复提交 | 同幂等键至多一个事件批次；不重复气泡/知识 |
| T13 | 两标签页同时操作 | 事务内版本比较防止覆盖；失败草案不得直接重贴新版本 |
| T14 | 卿成功、林晚超时 | 保留卿，只重试林晚；超时不落为剧情沉默 |
| T15 | 叙述失败或刷新 | 已提交动作不重复执行，正文从原场景包重试 |
| T16 | 改掉历史“取消打球” | 新分支从变更点前开始，不继承旧取消与后续传播 |
| T17 | 清空展示/撤回/世界回档 | 三者语义不同；已读撤回不让 NPC 失忆；世界回档恢复所有角色 |
| T18 | 摘要或向量服务失败 | 仍能从来源观察和原文继续；不回退到无权限的世界总提要 |
| T19 | 图片、语音、文档 | 资源引用、音色、发送者、观察权限正确；读者任务不自动代表角色已读完 |
| T20 | 地点问句/计划/时间跳跃 | 不自动到达；不从位置推出手机状态；未知保留 |
| T21 | 分支复制与备份导入 | 事件、知识、阅读游标、待办、卡/地图版本、附件引用完整往返 |
| T22 | 应用闲置、刷新、浏览地图 | 没有新 NPC 剧情事件或后台生成调用 |
| T23 | 长因果链与不断互聊 | 达预算/回应点结束；未决状态保留，不自我无限触发 |
| T24 | 开局卡及例句检索 | 范例不被当作旧聊天，未解决的人物槽位不绑定到玩家 |

世界事件重放应得到同一份必要状态。测试可以用固定 ID、固定剧情钟、固定随机结果及假模型回答，避免把供应商输出差异混进存储校验。

## 5. 真实模型评测

程序测试之外，使用隔离测试世界与合成资料，分别比较：

- 当前单卡实现；
- 多私聊＋RP 兼容桥接；
- 角色观察隔离＋完整角色模拟/叙述路径。

保持相同模型、参数、剧情起点与输入，记录真实请求和输出。初始可选择 10 个场景，每场景 3 次独立试跑；用于发现常见失败，不构成统计意义上的“彻底可靠”证明。正式模型调用及费用在实施阶段单独落实，本次没有使用模型服务。

判定维度：私密数据进入错误请求的次数、实际回复泄密/代写/错认发言人次数、误把提案当事实次数、角色口吻与动机质量、自然沉默率、P50/P95 延迟、总输入/输出用量与重试次数。

硬错误要求测试集中为零，但零观测不代表未来零风险。人格质量和自然度由人工阅读评定；可用辅助评审模型筛疑点，不能只让模型给自己打“通过”。多次采样出现不合理保密/泄密应检查上下文与角色设定，不能只调温度掩盖问题。

除最终正文外，还要核对模型实际收到的资料。角色没有说出秘密，却已在请求中读到秘密，仍属于隔离失败。

## 6. 可解释调试

调试信息应能直接显示：

```text
卿本轮为何不等玩家？
  来源：玩家→卿私聊 e201，卿阅读 e202，回复 e204。
苏祈雪为何仍以为打球？
  来源：玩家→苏祈雪 e100，阅读 e101；没有取得 e201 的观察。
林晚为何接在卿后面？
  调度：候选次序记录；林晚阅读卿 e204 后启动 run-L。
苏祈雪为何本轮没有回复？
  已记录的手机限制使阅读步骤延后；不显示技术故障为人物意图。
```

这是程序记录的证据，不是要求总 Agent 事后编一段心理解释。调试中的秘密只展示给使用者，不再次注入无权限角色上下文。
