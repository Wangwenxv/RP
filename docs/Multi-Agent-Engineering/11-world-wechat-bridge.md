# 世界 RP 的原生微信调用与界面交接

日期：2026-11-12。承接生日实测中大量线下剧情与微信交叉的场景。用户选择：角色联系玩家后自动打开对应私聊，并保留返回世界剧情入口。

## 当前行为

- 世界角色的 RP 决策提供原生 `tool_wechat`。`content` 是本人一条文字消息；`targetActorId` 可选择已认识的人物，省略时为玩家。发送者由绑定的角色身份决定。
- 每次人物决策接收一次有效发送。发送直接转为世界通信提案，经原有分支、版本、取消和权限检查提交；不追加同一人物的模型工具续写来编造收件人的回答。同批重复发送返回失败回执。
- NPC 联系玩家时设置玩家回应点。RP 正文保存后自动打开已有私聊；玩家可回复，或点击“返回世界剧情”。回到剧情后可通过“查看私聊”再次进入。导航本身不调用模型。
- NPC 联系 NPC 时保持世界剧情界面，由原有消息阅读与人物调度链路处理收件人的独立回应。未参与通信的人物不会得到消息原文。
- 手机不可用时不提供发送工具；伪造工具调用不能产生消息。两轮资料读取后仍保留发送工具，避免把发送误当成第三轮读取。
- 如果微信已落盘、旁白生成失败，先在剧情界面保留查看入口；恢复回合只处理未完成部分，不重复发送。刷新、切世界或切分支会清除临时交接提示，不把旧来信当成新来信弹出。

## 复用范围

原 RP 与世界 RP 共用 `wechat-protocol.js` 的主动文字校验：一条纯文本消息、换行不拆成多个气泡、拒绝嵌套 JSON 或发送者结构、沿用 400 字符上限。原 RP 的主动发送函数也使用这一入口。

世界接收与持久化仍使用世界事件存储及人物观察投影；原单卡发送函数依赖当前角色、旧微信时间线与旧分支，不能直接将它绑定给不同 NPC。原 RP 的被动多气泡、图片、语音及附件流程保持原入口；**本次世界工具只接文字，没有承诺完整媒体能力一致**。

原有 `tell` 通信提案继续兼容，已经通过该路径实际发给玩家的消息也适用新的界面交接。仅写在旁白中的“发了微信”不会制造会话记录或弹出私聊。
