# 角色自主维护自身位置

日期：2026-11-17。前置：[聊天地图抽屉](./16-chat-geography-map.md)。基础版本 `7c22501` 已发布；本轮用户明确授权修复、提交推送和线上真实验证，使用苏祈雪及已配置的 `qwen3.7-plus`。

## 用户要求与复现

角色就是当前人物卡，她可以不知道玩家在哪，但应知道自己的身体具体在哪里。对外只说「刚回北苑」，内部也应自主决定哪栋、楼内哪个位置；不能等待玩家追问，也不能只靠聊天文本正则猜位置。初始场景没有记录时，模型依据人物卡和已有剧情自主建场；玩家位置仍由玩家决定。

线上苏祈雪「地理地图实测-20261117」分支成功复现：询问位置后回复「刚回北苑」「吃过了」，追问又回复「3栋」「已经到宿舍了」，地图仍未知。旧实现只识别有限的正文事实句，也没有每轮自主场景协议。用户截图「刚才在吃饭」没有地名，不能推断食堂；截图模型服务 `model_not_found` 不代表更新成功。

## 本次状态契约

微信最终回复使用原消息协议，并在顶层增加内部 `position`，不显示为聊天气泡：

```json
{"messages":[{"type":"text","content":"刚回北苑"}],"position":{"action":"present","placeId":"dorm-4","detail":"一楼门口台阶"}}
```

- `present`：具体地图地点和场景细节，初始未知时自主选择；已经到达才能用。
- `stay`：保持已确认地点，可细化房间、座位等；首次建立场景需要 `present`。
- `depart`：从已确认地点实际出发，提供 `to` 和 `mode`；道路计算预计到达剧情时间。
- `continue`：维持已记录的在途行程。未走完路程不能提前变为在场；邀请和计划不是出发。

地图地点必须存在，片区和路网节点不能充当具体场所。新在场位置必须有短场景细节。已知地点直接切换要求足够已推进的剧情时间；缺乏时间证据先出发。打开页面、刷新或现实等待不推进剧情。`detail` 是人物可自主创作的场景描述，不是现实 GPS 或建筑设施数据库事实，也不输出模型思考过程。

同时提供 `tool_geo set_position`，参数为 `action/placeId/sceneDetail/to/mode`，不能指定玩家、不能放入 batch。RP 提示人物主动调用此工具；微信也可先调用它，之后最终 JSON 可省略重复 `position`。地图查询能看见本轮暂定位置。保留旧 `update_location` 核对已有正文事实。

微信缺失或非法位置会要求模型修正一次，再失败则不发送、不生成付费图片、不消费待回复消息。工具决定先暂存本轮预算，最终回复接受、播放首气泡时才落盘；API 失败不保存暂定位置。空回也有内部场景，保存于本轮最后玩家消息的回复决策元数据，所改变的是角色自身状态。

## 持久化与回放

- 首个角色气泡保存 `geographyPosition: {worldId, decision, storyAt, sourceContent}`；同轮后续气泡只保存 `geographyPositionRef`。空回保存 `geographyReplyPosition`。
- 回放先验证内部决定，之后同轮角色气泡不再用模糊口语覆盖具体场景。编辑/删除来源会使其位置失效；非法位置不能复活。
- RP 自主位置绑定当前 assistant 正文，工具续写完成后同步 `sourceContent`，避免追加文本使来源误失效。
- 刷新后打开 RP 地图会加载本分支的微信时间线，无需先打开微信。切角色、切分支与清空期间使用现有作用域及 revision 守卫。
- 微信已加载作用域改为响应式标记，避免地图先计算「未知」后，异步载入数据却没有触发重新计算。
- 人物卡次行展示场景细节。在途展示目的地及估计耗时，未知/歧义展示原因。

旧档兼容支持单卡微信「在图书馆看书」「刚回北苑3栋」「已经到宿舍了」等省略主语的事实自述；裸「3栋」仅在回答当前地点问题时采用。计划、疑问、过去、猜测、引用不定位；「刚回北苑」保留片区歧义。此回放仅兼容旧记录，新回复以模型内部场景为主。

## 文件与范围

- `assets/js/geography.js`：位置决定校验、路程时间、来源回放、工具 schema、旧档口语兼容。
- `assets/js/app/30-geography.js`：自身场景提示、微信最终决定校验、工具提交与预算。
- `assets/js/app/25-wechat.js`：一次修正、播放/空回持久化及失败隔离。
- `assets/js/app/15-generate.js`、`18-tools-ui.js`：RP 提示及工具续写来源维护。
- `assets/js/app/36-chat-map.js`、`assets/js/chat-map.js`：打开地图加载微信状态、展示场景细节。

沿用原生 UI，没有引入 CWUI。当前自主协议适用于单卡 RP / 微信；多角色世界抽屉仍读取原世界 `actorStates`，没有在本轮替换世界角色调度器。RP 依靠提示主动调用工具，微信则有最终结构校验。
