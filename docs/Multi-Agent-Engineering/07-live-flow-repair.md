# 世界微信与 RP 真实流程修复

日期：2026-11-11。用户授权在已打开的线上页面使用已配置模型实际测试。当前部署分支为 `multi_agent`，GitHub Pages 地址为 https://wangwenxv.github.io/RP/ 。

## 已确认的问题与修复

1. 最初页面只配置了识图模型，聊天槽位为空；服务商还返回账号验证 403。用户处理连接后，`qwen3.7-plus` 能实际回复。世界现在在保存输入前检查聊天配置，缺失时给出明确提示。
2. 新世界缺少开场白。新世界及尚无 RP 剧情的旧世界采用苏祈雪卡的 `first_mes`，解析世界人物绑定。开场白不写进全员观察集合。
3. 世界微信遗漏连发。现在使用原微信协议、分段解析、待回应计数和沉默归因；最多六条文字气泡。连发先保存玩家消息，“让对方回复”处理整批，失败可恢复。
4. 世界分叉清空可恢复回合后，把已回复旧消息重新计入待回应。现在依据历史 `turn.updated` 事件判断完成批次，分叉/回档保留正确处理状态。
5. 真实模型会写错长 UUID 引用，导致本来有效的微信回复被拒绝。微信直接采用原有 `messages` 协议；RP 提供短编号 `E<seq>`，只映射当前角色真正观察过的来源。
6. 世界没有自动人物总结。现在复用压缩提示词，从每个人独立的观察提取 `memory.summarized` 事件；原文、来源 ID、模型名同分支保存。RP/微信都注入近期与关键词召回，并可调用本人的记忆检索。总结失败不阻断对话，侧栏提供补录。
7. 叙述器没有得到人物位置；真实测试中角色选择等待，叙述器仍虚构了从教学楼离开的剧情。现在传入确定状态；没有已接受 NPC 新动作时直接输出保持现状，不调用模型补写。发生动作时明确限制地点、出发和到达须来自已接受事件。
8. 从 RP 页推进时间可能把当前 RP 会话当成微信。现在推进只结算实际待办与真正未读会话，手机限制按剧情时间解除。
9. 角色还可能把跨地点步行写入普通 `act`，造成旁白已出发而地图仍在原地。对有明确地图目的地的实际移动，校验要求改用 `move`，并向修复请求提供匹配的目的地 ID；未实施的打算仍可作为普通动作。真实复测中南苑13栋→三饭路线为3分钟，出发先记录途中与18:03到达待办。

移除原先硬编码的 2400 token 输出限制，沿用流式和推理深度设置；世界上下文预算默认 60000 字符，可在侧栏修改。人物、叙述、修复、读取续写和自动总结仍共同受每轮六次调用限制。对话优先，未完成总结保留原文供后续补录。生成期间会话按钮禁用，避免无意切换取消回复；页面显示当前是人物回应、组织剧情还是整理记忆。

## 保留的边界

世界模式目前使用文字、独立人物摘要与原文检索，尚未把旧模式向量索引、二次压缩和图片/语音/文档授权适配到世界模式。没有把旧单卡的全知记忆集合复制给每个人。模型措辞仍需场景评测，程序校验不能证明任意自然语言永远不含新增细节。
