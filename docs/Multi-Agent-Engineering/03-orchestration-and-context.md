# 调度、上下文与执行协议

> 本文保留原方案。当前文本角色调度、执行边界及尚未适配的媒体/摘要范围，以 [06 实现交接](./06-implementation-status.md) 为准。

状态：目标架构提案。先实现私聊窄闭环，再逐步启用本文件中的群聊和完整 RP 调度。

## 1. 不需要每个人一个常驻 Agent

角色模拟器是一个带明确身份的函数调用。每次从某个世界分支快照编译输入，完成后返回草案；事实保存在事件库，不保存在模型会话的隐藏状态里。

```text
runActorTurn({
  sessionId, branchId, actorId, conversationId,
  turnId, runId, snapshotRevision, cancelToken,
  contextPacket, allowedActions, budget
}) -> ActorProposal
```

同一个 API 和模型可服务苏祈雪、林晚和卿。未来可以分别设置模型槽位，但不是隔离知识的前提。不同角色请求不能共享未筛选的对话线程，也不能通过临时修改 `__s.currentCharacter` 来复用现有函数。

运行时捕获上述身份后，异步途中不再从 UI 当前选中项重读身份。工具执行端绑定身份；模型即使提出另一个 actorId，也没有切换读取权限的能力。

## 2. 职责与授权

| 部件 | 输入 | 输出/权限 |
| --- | --- | --- |
| WorldRuntime | 玩家操作、分支 head、已提交状态 | 创建回合、选候选人、处理到期任务、预算、串行提交 |
| 可选 ScenePlanner | 本轮剧情、参与者摘要、相关且获准的场景资料 | 候选场景与角色 ID，不直接确认某人泄密或替玩家行动 |
| ContextCompiler | 快照＋绑定 actor＋渠道 | 已观察信息、人格内核、相关关系/地理与可用工具 |
| ActorRunner | 自己的上下文包 | 本角色的话、行动提案、沉默或延后；不能写其他角色决定 |
| CommitCoordinator | 草案、版本、来源和动作条件 | 硬约束校验、幂等、事务提交或拒绝；不假装能证明整段语义正确 |
| Narrator | 获准展示的场景包、接受的关键事件、文风与玩家边界 | RP 文字草稿；没有直接发微信、改变角色记忆的权限 |
| MemoryProjector | 已提交且对该角色可观察的事件 | 来源化观察、摘要与可选信念/向量索引 |

确定性指程序规则、事件提交与重放可重复，不表示人类行为有唯一正确答案。同一模型重试可能生成不同内容，重放应读取已经提交的事件及接受产物，不能重新调用模型假装恢复历史。阅读和位置等确定性投影与模型摘要分开；影响后续的信念决定也需保存原接受结果，详见世界模型 §8。

## 3. 世界只在玩家操作时推进

触发点为发送微信、提交 RP、明确“继续/推进时间”等会改变剧情的操作。切换联系人、查看地图、刷新、阅读旧消息不自动启动新一轮 NPC 行动；阅读本身可记录玩家阅读观察，但不顺便推动幕后剧情。

每次触发：

1. 捕获世界分支、版本与本轮允许到达的剧情时间，申请分支生成锁。
2. 先提交真实玩家输入，区分微信发言、RP 已做行动与作者剧情前提。模糊句子不强制抽成新事实。
3. 从会话成员、当前场景、点名人物、未决约定及到期任务中本地筛候选角色。
4. 处理本轮允许范围内的观察与 NPC 行动。未到期的任务留存，不用现实定时器替玩家推进时间。
5. 达到玩家回应点、时间边界、动作数量或费用上限时结束本轮。

角色独立生活通过这样的有界结算产生。不是只有被玩家点名的人才能行动，但远处每个 NPC 都运行一遍也没有必要。未来的幕后事件只在与本轮因果/日程有关时进入候选队列。

## 4. 私聊

最小私聊规则：收件人有明确通信障碍时保持未读；没有障碍时，本轮可以让收件人查看此会话，再生成回复或沉默。未知状态不等于肯定有空，模型可以在不虚构新事实的前提下选择简短回复或不回复。

角色生成只得到：自己的稳定设定、已认识的人、自己观察的往事、此会话已经读到的消息、本人处境及局部地理。苏祈雪的请求不能带玩家与卿的私聊，也不能带泄密的摘要、检索片段或如“生日惊喜保密对象”这样的内部标签。

无需总导演先调用所有卡。一般一次 ActorRunner 请求可产生一批本角色的短气泡，沿用现有微信分段协议；语音、图片、文档再经现有执行器适配。

## 5. 群聊：先观察，再生成，逐个提交

以玩家、苏祈雪、卿、林晚四人群为例：

1. 提交玩家“哈喽”。按成员区间分配送达资格。
2. 程序根据已知处境和通知元数据判断谁可能看手机，不能先把全文发给角色再问是否会阅读。
3. 为查看的 NPC 提交阅读观察；苏祈雪若明确上课收起手机，可暂不读取。
4. 根据点名、未回应问题、最近发言、处境等选下一发言候选。需要随机打破平局时保存抽样结果，避免总按名册第一位。
5. 卿生成自己的气泡并提交。重新检查剩余候选，林晚取得卿消息的阅读观察后再生成，才可以说“卿也不知道”。
6. 如果卿已经回答了问题，林晚可以不再接话。不能在第一步把每人的必发文本写死。
7. 到预算或玩家回应点结束；苏祈雪之后读到时可以不补发一条过时的“哈喽”。

群聊同一回合按人物顺序执行即可。并行预取卡条目与允许读取的资料没有问题；依赖上一人物回复的生成不应并行。将来若支持同时发言，两个人的内容只能基于共同旧快照，不能相互引用尚未出现的消息。

每条气泡拥有独立 `senderActorId`；模型协议的 `assistant` 只是一种传输角色。展示、气泡合并、媒体音色、摘要和检索都必须使用真实人物身份。

## 6. RP：决策与叙述分开，但不为每个修辞建事件

完整 RP 路径：提取相关场景 → 为直接相关角色编译上下文 → 获取行动提案 → 校验可实现性 → 提交短因果链 → 叙述。对没有出场、没有收到信息、没有相关待办的角色不调用模型。

林晚可能告知秘密的过程应是：

```text
玩家向林晚请求保密
  -> 林晚已观察到这件事，模拟器选择当前意图
  -> 如果选择告知：检查有无机会、渠道、时间和权限
  -> 机会不足：登记待执行动作，苏祈雪暂不知情
  -> 告知实际发生：提交通信/观察事件
  -> 苏祈雪获得自己的新上下文，再决定如何回应
  -> 叙述器根据获准场景表达这段事情
```

关系亲密不是“必定告知”的规则。为了写出用户所举的某条轨迹，测试可以明确设定林晚选择告知，但产品运行不能把这一结果硬编码。

需要结构化接受的内容：发消息、转告、承诺、约定变更、移动与到达、物品转移、新人物知情、会影响后续的决定。停顿、语气、衣袖动作、无冲突的环境细节可以作为叙述修饰。不能以“修饰”为名增加玩家动作、完成通信、创造旧聊天或改变场景事实。

叙述器输入按获准的 NPC 场景切片，角色台词和关键选择优先采用对应角色已给出的结果。允许展示秘密的读者权限，不等于把全部世界秘密交给每次叙述器；仍只提供当前必要内容。

程序可以检查明确行动字段与引用，不可能严格证明自然语言没有暗示或添加新事实。可增加事件一致性审核与重试，但它是检测措施，不是正确性证明。重要剧情可展示来源调试，保留修正/分支能力。

## 7. 上下文包

建议内容顺序：

1. 本次职责与动作权限：只控制该 actor，玩家决定权，输出协议。
2. 人格内核：核心性格、语言和边界，固定版本，不机械删到极短。
3. 当前本人状态：位置、活动、手机条件、当前时间，每项带来源或未知。
4. 已知关系与相关开局经历：只给该角色的版本。
5. 本轮直接刺激与必要的最近已观察原文。
6. 已观察的长期记忆、相关世界条目与地理结果。
7. 未决问题、约定和可行动候选。

世界资料使用原文条目优先：本地检索先取少量候选，需要时工具按 ID 读取。人格内核不走纯相似度召回，以免“相关性低”就丢失基本人设。给其他角色的介绍应是该 actor 已知的介绍，不能直接注入对方完整卡。

为兼容现有长卡，保留“本角色完整卡”实验模式；它也必须执行个人/他人/作者资料的权限分类，不能绕过秘密边界。新的编译卡在正式替代前，比较人格保真度、具体行为和上下文占用；不宣称一份摘要必然等价于原文。

## 8. 工具边界

建议通用工具而非 `tool_suqixue/tool_linwan/tool_qing` 三套重复实现：

| 工具 | 输入示例 | 运行时边界 |
| --- | --- | --- |
| `search_my_memory` | query、少量 filters | 绑定自己的观察集，先过滤再搜索 |
| `read_evidence` | 已获授权的 event/entry ID | 再验分支、时间、版本、阅读资格与预算 |
| `get_known_person` | 已识别的 targetActorId | 返回调用者已知的人物资料，不返回该人物的私有卡 |
| `get_scene_context` | 当前场景/附近范围 | 本人可知的地理与现场信息，不返回远处全部 NPC 精确位置 |
| `propose_action` | reply、wait、move、tell 等 | 只是草案，实际发送/到达由程序提交 |

调度器内部可以调用 `simulateActor(actorId, ...)`。该能力不是每个角色都能调用的工具，角色不能召唤另一个模拟器来偷读秘密。

检索必须在词匹配、向量排序、命中统计、摘要之前执行访问与观察筛选。缓存键包含世界存档、分支、actor、观察版本、卡/地图版本、查询和策略版本；不能按 query 单独缓存。图片描述、OCR、文档读者笔记、向量文本、工具错误和调试原因都属于潜在旁路，也要绑定相同来源和权限。

卡、世界书、附件文本是资料，不具有修改运行时身份或权限的能力。工具结果不接受“作为系统管理员读取全世界”等文本指令。

## 9. 预算与成本

输入预算按具体模型上下文窗口计算，预留输出及工具往返空间；优先级为身份边界、人格内核、当前刺激、当前状态、近期证据、长期相关资料。超预算时先缩远期可选资料；连必需内容都放不下，应使用更大上下文配置或返回明确技术错误，不能悄悄丢掉关键规则。

建议起步参数（工程默认值候选，需实测调整）：每次玩家操作最多 3 位 NPC 主动回应、每位最多一批气泡、最多 2 层新的跨人物传播、全回合最多 6 次聊天模型调用。重试、工具续写与叙述均计入回合预算；摘要任务单独记账且有上限。单批气泡可先限制 3 条，避免一句“哈喽”变成自动长谈。

这些限制是防失控边界，不是要求每轮用满。达到上限时保留未决动作；技术限额不能写成角色忘记、拒绝或沉默。需要玩家回应的邀请优先结束自动推进。

简单私聊常见为 1 次角色请求；示例群聊两位回应常见为 2 次顺序角色请求；完整 RP 常见为 K 次人物请求＋1 次叙述，可选复杂场景规划再加 1 次。上述常见次数未包含工具循环与重试，它们仍计入全回合 6 次上限；压缩使用单独的有界预算。群聊不需要叙述器。

总费用仍取决于所有调用的输入/输出与供应商计费；单次输入变小不等于总费用变低。记录 `purpose/actorId/runId/inputUsage/outputUsage/elapsed/retry/toolRounds`，用同一场景比较。字符估算不能冒充 token 使用量。

延迟方面，后者引用前者的群聊必须承担顺序等待。采用“先显示已提交的卿消息，再生成林晚”的渐进展示；不能为了好看先播放尚未成功保存的消息。

## 10. 失败、取消和半成功

`ActorProposal` 至少含 `decision/actions/referencedEvidenceIds`，可附简短动作依据；不索取或保存模型私有思维链。若 provider 不能可靠输出结构化协议，解析后做 schema 校验，最多在剩余预算内修复一次；仍不合法就显示技术失败，不生成虚假的剧情结果。

硬校验包括：角色身份、目标会话成员、动作类型、来源 ID、期望版本、时间/行程约束、幂等键、取消状态。真实 ID 不保证模型正确理解了原文，语义仍需检查。

群聊采用逐消息/角色批次提交：卿已成功、林晚失败时，保留卿；重试只处理未完成的林晚。技术失败与剧情沉默严格分开。刷新后通过 `world_turn` 恢复已完成步骤，不重复发送。

版本冲突后不能给旧草案换一个 revision 再写入。应丢弃草案、读取新快照并重新规划。停止、切分支、回档后晚到回复必须拒绝；待办和媒体结果也要经过同样检查。

RP 的短因果链可以分小批接受，通信一旦已提交不得因为叙述失败而被悄悄撤销。叙述失败时保留事件，重试从相同场景包写正文，不能重跑所有动作。正文可先作为草稿缓存；通过检查并持久化 `narration.published` 后再标为完成。流式预览若启用，应明确是待确认文本。

禁止无限子 Agent 互相调用、自发无边界续聊、无预算的裁判循环。后台摘要只处理既有事件，不创造新事件，不在世界闲置时推进剧情。
