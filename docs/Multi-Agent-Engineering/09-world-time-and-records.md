# 世界时间、视角与记录操作

2026-11-12。承接 08 的界面与保存优化，新增统一时钟、连发间隔、记录编辑/清空及版本回收站。

## 时间与连发

主界面时钟对同一世界分支的 RP、全部私聊和群聊共同生效。普通模式的时间推进处理已到期行程、未读消息与人物独立场景，并发布 RP 叙述；刷新、读档和浏览不调用模型。

连发模式下，时间条的 +5 / +30 分钟及「推进到」**只保存时钟，不调用模型**。例如 18:00 发「老！婆！」，+5 分钟后发「喂喂喂，老婆人呢？」，最后「让对方回复」。每条消息保留原时间；角色上下文同时携带当前时间、第一条待回应时间、最近收到时间及未回应分钟数。也可在输入区直接指定下一条消息的发送时间。

Enter 发送，Shift+Enter 换行。IME 正在选词时 Enter 不发送。聊天输入区压缩为两行，空私聊显示顶部的小提示。

## 玩家与作者视角

玩家视角下，勾选表示“谁能看到/听到本轮输入”，不强制人物行动。所有启用人物仍可根据自己的见闻继续场景；未勾选人物不获得原始输入。可以全部取消，写独处行动。

上帝视角输入保存在玩家的作者来源中，原段落不直接交给各人物。新增 `world-director.js`：只读取作者输入、人物 ID/名字和公共地图，提取明确的个人状态；不读取私聊。每个状态须有连续原文引用，非玩家必须明确具名，地图地点必须存在。所提取的个人事实只授权对应人物。未具名的「关闭手机」默认玩家；夜晚到来不能解释为全员关机。模糊的“夜晚”不自动猜具体钟点，请使用时钟控件。

角色可通过本人已接受的 act 同步手机/活动状态。跨地点移动仍用 move，并验证路线和到达时间。位置从未建立的角色可用 act.state.position 建立自己符合人设的初始场景，来源标记 `npc_scene_start`；已有地点不能用此方式覆盖。作者手动状态入口折叠为「作者修正人物状态」，供纠错而非每轮必填。

RP 中 NPC 实际发送的私聊，会让合法收件人阅读后继续自己的 RP 行动。收件人若已经完成一次场景，可在有新通信时再响应一次；防止“卿告诉林晚，但林晚本轮始终无法读到”。产品回合最多三个初始人物、六个决策步骤和十八次总请求；重试沿用步骤，不重复已成功的动作。

## 编辑、清空与版本

每条可见私聊/群聊消息、玩家 RP 输入与叙述都有编辑按钮。保存修订原子创建新分支，保留到修改点，回退所有渠道的后续剧情、状态、记忆与未完成回合；原分支可恢复。正常微信的 player.input / message.sent 镜像同步修订，不能出现两个不同原文。修改 RP 玩家输入后可「继续这一幕」，不重复生成玩家输入。

叙述修改用于修正文风，不改变原本已接受的人物动作；需要改变剧情时编辑对应玩家输入并重新回应。界面明确说明这一点。

「清空世界记录」建立新的空历史分支：清空 RP、全部私聊/群聊、人物记忆、待办与回合；状态回到开局，卡牌、头像、会话和当前时钟保留。旧分支留作恢复。不会仅隐藏气泡而让人物仍记得已清空的事件。

设定/角色卡修订的**版本**与剧情选择的**分支**不同。删除版本会连同其中全部分支移入回收站，可恢复；不会删除其他版本。回收站记录仍使用原世界存储结构并可完整备份。

## 与原 RP 的边界

旧 RP 的交互、摘要/检索、媒体附件、分支与清空逻辑没有接入世界事件。世界使用独立存储命名空间，复用共享 API 客户端、微信气泡协议、时间/地图工具。

世界上下文仍是每人独立见闻 + 原文检索 + 人物总结/关键词召回，**不等同于旧 RP 的完整简化工程**。世界暂只支持文字消息，尚未接入旧 RP 的图片描述、图片原件/附件、语音与文档处理；不能宣称媒体能力已经一致。

## 生日实测后的修复

提交 `eaa3abb` 已部署到 `multi_agent` 的 GitHub Pages 页面。人物最多进行两轮资料读取，之后移除工具并请求最终提案，为其他人物和旁白保留单轮预算；违反最终提案要求仍按技术失败保存，可继续回合，不伪造角色沉默。

RP 地图预取同时参考本人近期已观察的消息，便于执行微信中约定的行程；未读和他人私聊不会参与预取。人物决策优先考虑近期实际收到玩家消息的人物，减少先执行无关独立场景、再反复回访的请求。

到期的 act、speak、remember 及尚未出发的延后 move 也会唤醒本人重新决定；已审议的旧计划标记完成，不盲目重放未来动作。移动目标须为地图中有效 ID。旁白仅接收未实施计划的元数据，避免把延后动作正文当成已经发生。

RP 输入保存原场景人物集合，修订后继续时恢复这些人物；全文见证范围仍按原输入保留。早期作者输入没有该字段时，回退为启用人物的独立场景，避免无人回应。

实测验收按用户后续明确的标准：剧情逻辑合理、人设连贯、没有重大错误即可。微笑、整理物品等合理演绎不要求逐字对应动作事件；生日秘密传播、时钟、通信渠道和重大地点变化仍需核对。

提交 `3a91757` 修复 NPC 主动私聊玩家时新建第二个同名联系人的问题：先按两个参与人物查找已有私聊，再决定是否新建。双方通信和访问权限不变。
