# 地点简介预取与楼内房号交接（2026-11-06）

用户截图中连续发送“你在图书馆吗？”、“我在B栋401”，没有看到工具调用，希望确认模型是否会读取地点功能和环境。

## 诊断结果

已有提示词规定：本轮地理速查够用时直接回复，不重复调用 `tool_geo`。速查是浏览器本地计算后放进本次system提示，不产生模型工具调用记录，也不额外发识图/检索模型请求。因此没有工具图标不能证明没有提供地理资料，也不能据此断言模型认为地点不重要。截图本身无法证明某次已完成请求具体收到哪些资料。

用截图消息复现当前代码，发现两个缺口：

1. 地点提及匹配能找到“B栋”，但严格当前位置匹配把“B栋401”整体当地点，返回 `unknown_place`。
2. 自动预取只查看最后一条用户消息。在微信连发模式下，最后一句B栋会覆盖前句图书馆的预取机会。图书馆可能出现于B栋出发的分钟表，但分钟表没有图书馆功能与环境。

## 本次修改

- `geography.resolve`在完整地点精确匹配之外，支持**准确的已知地点名/别名＋3或4位房号**。例如“B栋401”、“B栋 401教室”、“B栋-401室”定位到教学楼B栋，并保留 `subLocation.room: "401"`。若地图有精确的B栋401地点条目，优先用该条目。房号不提供房间功能、存在性或室内测绘的保证，路线只计算建筑间通行，另提示楼内时间未建模。
- `project`与`briefState`保留房号证据。问句“我在B栋401吗？”、计划“我要去B栋401”、对角色的询问“你在图书馆吗？”不初始化当前位置。
- 新增 `geography.mentions`，一次识别最多4个不同地点，去掉同一地点重复别名及被更长别名覆盖的匹配。原 `mention`保留兼容。
- 微信预取读取本次未获角色回复的一批文本，最多8条、4000字符；从最后一条向前读取，遇到本频道的角色回复停止。RP继续读取最新一条用户文本，该条内可识别多个地点。
- 预取保留原context的位置/路程/常去地点分钟表，并增加 `mentionedPlaces` 中本批提及地点的简短用途、环境和开放规则；整体遵守既有brief资料预算。单独的图片附件不会重新激活已回答的旧地理话题。
- 提示词说明：提及地点不等于确认在该地点；资料帮助角色的反应贴合场景，普通聊天无需讲解地图。具体设施/楼层缺资料时按需查 `place`、`detail:full`，没有建模的事实不得编造。

应用于截图：玩家位置为教学楼B栋，房号401；B栋提供中文系教室与办公室及短环境；图书馆提供借阅/自习、短楼层背景、22:30闭馆及通宵自习室例外。**不会把“你在图书馆吗”当作角色已在图书馆。** 是否进一步主动调用完整资料仍由模型决定，不承诺每次都调用或复述场景。

这次没有加载整张地图图片，也没有强制每次多一次模型请求。自动短资料仍占本轮输入token；较长文化/详细设施仍按需查询，工具结果不写成聊天气泡或长期地理记忆。
