# 玩家决定权与防代写交接

更新：2026-11-07。本次沿用原有 UI，只修改提示词、请求组装与记忆素材来源；本工程不是 CWUI。

## 世界仍可自主发展

后续澄清已落实：玩家决定权限制模型控制玩家，不要求所有人物围着玩家或暂停生活。RP 可切到分开后的角色/NPC，连贯展开独立事务；自然需要联系时通过微信工具发送角色消息，只有相关互动需要玩家选择时才留在回应点。叙述者展示不等于人物知情，微信回灌与三类压缩同步保留认知来源。设计、修改入口与实玩判定见 [世界自主叙事交接](./rp-world-narrative.md)。

## 排查结论

原有“防抢话”预设已经禁止新增玩家言行，但存在几个容易让模型偏离的入口：

- COT 一边要求分析玩家的“潜台词、情绪和真实需求”，一边要求不得擅自解释真实意图；剧情规划中的“选择、行动”也未明确限制主体。
- “去User中心化”允许 NPC 不等待玩家而自行推进，容易被泛化成玩家也跟随行动；地理建议中“由人物性格决定”同样需要限定为 AI 角色自己的行为。
- RP 防抢话取决于预设是否启用。微信只使用角色勾选的 `wechatContent`，原防抢话预设没有微信版本，所以 RP 开关不代表微信有同样约束。
- 逐轮总结要求保留行动、决定和心理，但缺少玩家原输入核对规则。二次压缩原先只发送摘要；RP 前情提要素材原先没有标明哪段是玩家原输入、哪段是 AI 叙述。模型曾代写的行为可能在压缩后继续被当作事实。

这些是代码中确认的提示词边界与素材来源缺口。首次修正时没有具体违规回复；后续用户提供了模型替陈璃答话、离开实验室、发微信及补出已读结果的样例。本次按该样例继续清理冲突，但缺少那一轮完整请求，不能断言某一项是唯一原因。

## 陈璃代发样例的进一步修正

用户要求：宁可少量推进，也不能替玩家说话或行动。复查发现上一轮遗漏了两种强制进展压力：

- `15-generate.js` 对包含 DeepSeek 的模型名额外注入“正文最少700字”。这是一条应用提示词，已经删除；不是模型必须完成的 token 指标。
- 文风预设要求每轮事情、认识或关系有实际进展，苏祈雪卡的“恋爱日常”条目又要求每一到两轮至少完成一项甜的互动。其日常仪式还列有“他回早、他来图书馆、他多打一个菜”等双人示例。这些不能成为本轮玩家动作的授权。
- COT启用时，普通历史原先还会重新注入最近两轮模型的分析。旧推测和待行动方案可能被反复当成续写依据；现在普通历史只发送正文，不重新注入旧COT或旧原生思考。原聊天思考记录、当前分析流程、开场的静态流程示例，以及本轮原生工具必要推理/签名不删除。

修正后允许单次NPC反应、保持现状、短回复与等待玩家，玩家决定点优先于字数、完整一幕、关系进展和互动数量要求。活人感中的“有来有往”只适用于NPC，不补写玩家下一句。

共享约束单独规定：没有玩家明确给出或授权，不得新增以玩家为发送者的微信、短信、语音或对白，适用于姓名冒号、引号、第三人称、时间戳、HTML与工具等形式；也不补写玩家掏手机、打字、发送、追加消息及因此虚构的送达/已读。玩家自己明确发出的消息仍可承接，读到与否另须事实依据。总结也同步核对这种“姓名：消息”的来源。

RP 使用 `appendPlayerAgencyPrompt(..., { includeTurnReminder: true })` 在最终玩家消息末尾追加 `<player_turn_boundary>`，具名区分玩家与AI角色。已有用户内容、来源索引及图片不改写；原生 assistant/tool 消息保持顺序和签名，不为续写伪造新用户回合。此提醒只在发送上下文中存在，不写回聊天正文。

磁盘 `card/suqixue/苏祈雪.json` 的本次文案修改包括：人格正文前增加全卡玩家控制边界和后续补充的“世界与镜头”；“每一到两轮至少落一条”改成按情境选用的表现方式。其他JSON值和原格式保留。前史仍是过去背景，日常示例和反应矩阵不能反向制造玩家当前行为。

例如卿问“现在去吃饭？”时，如果玩家没有给出回答，可以停在卿等待回应，不能继续替陈璃说“嗯”、离开实验楼并向苏祈雪发消息。

## 当前行为

每次 RP、微信与工具续写请求都带 `<player_agency>` 系统约束，独立于可选预设和 COT 开关：

1. 承接玩家明确写出的台词与行动，只处理其客观后果和其他角色的反应；明确一步不会自动授权下一步。
2. “想、考虑、打算、如果、要不要”等保留意向、条件或问题的含义，不自动变成执行、到达或同意。
3. NPC 的邀请、命令、期待，玩家的拒绝、犹豫、沉默，以及模型推测均不能授权玩家行为；“下意识”“其实想要”等解释也不能绕过玩家边界。
4. NPC 可继续独立行动，环境和外力的客观结果可发生；这不等于玩家自愿配合。需要玩家选择的相关互动停在可回应的位置。
5. 当前明确更正、拒绝、撤回优先。旧 AI 正文、COT、开场示例、摘要、微信回灌、UI 状态和工具路线不能反向授权新行动。
6. 玩家主动要求代写或托管仍可使用，但限于明确范围与期限；普通“继续”、要求更多字数和功能开关不会自动成为授权。
7. 允许少量推进和短回复，不设每轮最低篇幅或进展指标。玩家的新微信与台词不能因为恋爱惯例、NPC期待或推理而出现。

微信明确“你”指 AI 角色、“对方”指玩家，玩家姓名从真实用户设置传入。JSON、表情、沉默、媒体与发送时间协议保持原有行为。

RP 约束拼到现有第一条 system 消息末尾，不改变普通消息顺序、`tool_call_id`、原生工具签名或来源元数据。每次 `generateResponse` 重新组装一次；工具续写也经过同一入口。不要在用户正则之前注入，也不要把它降级成可选 COT 内容。

总结规则共享玩家来源校验：玩家的自愿行为、决定、心理须有原输入或明确授权支持；意向、拒绝、条件和未决状态不能压缩成完成。二次压缩核对材料只校验对应摘要，不扩大总结目标。缺少来源的旧玩家决定保持未确认，不能凭空补造证据。

每个主请求增加一段固定约束，RP还增加简短的最终玩家提醒；总结请求增加来源规则，二次压缩还增加对应的玩家原输入，因此输入 token 会有所增加。没有新增纠错模型请求，也没有通过关键词删除正文。

## 生效与旧记录

刷新页面即可加载新脚本，内置预设由现有启动同步更新。无需开新聊天或手动重新勾选“防抢话”，原启用状态不变。

已导入的角色储存在浏览器数据库中，不会随磁盘JSON自动更新。程序中的玩家边界、世界叙事、篇幅优先级和最终提醒对已有角色也生效；如需同步角色卡内部的新文案，可在现有角色编辑器同步人格开头和恋爱日常条目，或按现有导入流程导入更新卡。不要为了同步这些文案删除现有聊天。

历史正文、已有摘要与变量不会被自动改写。若旧记录已经把玩家写成同意、出门等，优先编辑错误消息或总结；已有错误前情提要可用现有删除入口清除，校正正文后重新压缩。当前消息也可直接澄清实际状态，例如“我没有答应，也没有出门，仍在房间”。

提示词约束能降低代写倾向，不能保证所有模型每次都遵守。此轮验证的是实际请求确实包含约束、来源标记与授权规则，没有调用真实服务评价输出语义的改善比例。
