# 微信语音连接报错：配置恢复与真实聊天验证

> 日期：2026-11-03。关联：[语音完整交接](./wechat-voice.md)、[本机按需运行](./wechat-voice-local.md)。本轮使用用户已启动的服务与原 GitHub Pages 内置浏览器标签页。

## 现象与排查结论

用户截图显示“无法连接语音服务，请启动本机服务并检查微信设置中的服务地址”，并保留待发送文字和语音原文。此提示来自客户端 `fetch` 的网络异常，不是聊天模型没有生成语音，也不能仅凭提示认定 Key 或音色失效。

本轮接管页面时，微信设置里的服务地址与 BreezeBlue Key 都为空；角色语音开关开启，已选音色 ID 仍在。填入当前运行实例的 HTTPS 地址后，读取目录先明确提示缺少 Key。用户在原页面自行填写 Key 并保存，本轮没有读取、输出或写入文件中的 Key。

确认本机服务正常、HTTPS health 标记正确、Pages 的 health 与 OPTIONS 来源许可通过后，原页面成功读取 30 个中文公共音色，原音色“京巷秋声”匹配目录。保存当前配置后，真实聊天和语音合成均成功。

早期终端探测曾遇到连接重置，后续 Node 和内置浏览器探测通过。没有取得截图发生时的请求日志，因此不能进一步断言原始失败是旧地址失效、临时网络波动还是当时的其他配置问题。本轮确认的是当前配置恢复后链路可用，无需修改合成代码或重启用户服务。

## 真实验证

按用户要求，以连发模式提交三条消息，再触发一次回复：

1. `10点呢`
2. `晚姐给我留饭！`
3. `想听你说句语音`

真实聊天模型返回两条文字：`行，给你留着呢`、`十点钟下课赶紧回来`，以及一条真实语音，气泡显示约 **5 秒**。展开原文为：

> 知道啦，给你留了饭，下课赶紧回来啊小孩，路上慢点。

语音播放进入 `aria-pressed=true` 的播放状态，手动停止成功；关闭并重新打开微信后，同一气泡仍可读取。没有再次合成，转文字展示原合成台词。此次流程没有出现浏览器 error 日志或失败批次。

本轮调用了真实聊天与 TTS，会消耗正常服务额度。保留用户要求发送的聊天消息与音频。连发模式在测试后恢复，用户启动的语音服务保持运行。

## 后续遇到同类报错

- 保留原 Pages 页面，在微信设置确认当前服务地址与 Key 已填写并保存；角色的音色 ID 保留不代表标签页的 Key、服务地址也还在。
- 每次重启本机服务，使用启动窗口或 `.refactor-tmp/wechat-voice-local/service-url.txt` 中的当前地址；临时域名不要当固定地址。
- 先读取中文公共音色确认连通性，成功后保存。已有失败批次用“重试发送”，无需重新向聊天模型请求相同回复。
- Key 与服务地址使用 `sessionStorage`，只属于当前标签页会话。新会话可能需要重新填写；避免把凭证加入角色卡、日志或交接文档。
