### 证据支持的原因

1. **提示词限定了照片身份结论。** `27-wechat-media.js` 的参考目录、参考工具附件和独立核对临时system提示分别含“不能凭照片确定真实人物身份”“不做真实人物身份判断”“不得把……写成‘确认是我/本人’”。核对只提供画面观察，并不承担选出本人照片的任务。将三张图配置成角色参考，不等于当前链路授权把陌生上传照片直接归为角色本人。
2. **模型从不确定越界推断为否认。** 返回文本先写“按照规则，不能凭照片确定真实人物身份”，随后写“这些照片明显是网上找的图”“她知道这些都不是她”。“网上找的图”和确定不是她均没有工具来源依据；这也违反了同一提示中“没有依据时保留不确定”“不为制造疑问而否认每张照片”的要求。最终否认已在原始JSON中出现，前端没有把肯定答案改成否认。
3. **模型优先使用角色卡的固定外貌文字。** 诊断文本多次列出“齐肩细软黑发、白瘦、眼睛不大”，随后以照片长发等造型差异否定。角色参考存在，但主模型仍需主动选择参考工具；诊断分支没有选它。主线选了工具、拿到三张参考后仍否认，因此缺少参考输入只能解释部分链路，不能作为统一根因。
4. **重放另有工具参数兼容问题。** 模型传入 `#5cb5ecba-...` 等带展示前缀的 `messageIds`；执行器按 `item.id === id` 严格匹配，消息实际ID没有 `#`。因此返回“图片不在本角色的当前会话中”，模型随后写“图片查看失败了”。四张新图此前已经直接进入主请求；这个失败不意味着本轮完全没有图片，也不解释主线参考工具成功后仍否认。
5. **独立核对两次超时。** 两轮都未取得有效核对资料，后续收到的是失败规则，而不是逐图观察。主请求仍有四张像素；不能将核对超时描述为整个视觉输入丢失。大量角色/预设文本也同时在场，诊断初次主请求返回的usage为34530个输入token，其中图像3187、文字31343；这显示上下文规模，未做消融实验，不能据此量化哪段文字造成否认。

因此当前结果支持“提示边界、角色卡文字优先和模型错误推断共同影响”；没有提供跨图身份辨别正确率或纯视觉能力消融结果。

## 微信分支：独立保存与继承遗漏是两件事

微信权威记录存于 `wechat_timeline`，作用域与剧情分支一致：主线使用角色UUID，子分支使用 `角色UUID__branch__分支ID`。切换使旧内存作用域失效，再读目标分支。

本轮在用户已有页面完成 主线→外貌认知流式诊断→主线：诊断分支恢复“你从哪找的这些”；主线恢复“怎么了”及“你拿谁的照片来考我”。两条分支没有互相覆盖，原消息和图片均可见。最终页面恢复苏祈雪主线微信，截图为 `branch-restored-main.jpg`。

但 `21-character-lifecycle.js:createStoryBranch` 只读取/复制 `chat` 和 `classic_memories`，以及模板runtime；没有读取、裁剪或写入 `wechat_timeline`。所以新分支没有微信记录，首次打开只会补充RP镜像。

隔离复现使用真实21、25模块和fixture存储，脚本为 `.refactor-tmp/suqixue-self-awareness/verify-branches.cjs`，结果见 `branch-verification.json`：

- 将一条微信放在RP分叉点**之前**，从后面的RP答复创建分支：3条RP复制成功，微信继承0条，原分支保持完整。该实验排除了“微信本来发生在所选历史分叉点之后”的解释，确认继承遗漏。
- 已有两条分支互切，恢复各自微信文本，未混入另一条分支。
- 模拟在300毫秒自动保存执行前切换：保存任务捕获旧scope和旧数组，之后写回原分支；目标分支未污染，切回恢复。当前切换函数没有显式调用 `flushPendingWechatSave`，此复现没有证明进程突然关闭或存储写入失败也可靠。

用户这次点击的“从这里分支”位于RP开场白，微信对话在开场之后；如果采用严格历史回档语义，回到开场点本来就不该带上未来微信。但当前实现对**所有**新分支都不复制微信，即使微信发生在分叉点之前也一样，这是实际缺陷。当前页面也没有微信气泡处的分叉入口，无法直接表达“从这条微信继续另一条分支”。

## 2026-11-24 补：外貌认知提示词改为同源比对（仅聊天链路）

用户判定原设计前提错误：参考图应被当作**本人长相基准**，模型应逐张比对上传照片，判断是不是她自己；「不能凭照片确定真实人物身份」不应存在。

改动只在 `assets/js/app/27-wechat-media.js` 的微信聊天链路，**未改** `assets/js/image-generation.js`、`card/suqixue/苏祈雪v2.json` 与任何生图请求格式，因此 2026-11-23 的自然语言生图适配（16 张参考、身份/偏好/场景分层、`selfPortrait`、`scene` 校验、NAI 正反词清理）不受影响。

| 位置 | 改动 |
| --- | --- |
| 参考目录（`buildWechatMediaPrompt`） | 参考图改为「本角色长相基准」；要求先取参考像素再逐张比对稳定面部特征；非人物图不做身份比对；只有 `same` 才承认，`likely/uncertain` 保留不确定 |
| 参考工具附件与返回 | 去掉「不做真实人物身份判断」「不能凭照片断言人物身份」；完整数据不一致只说明不是同一份文件，不代表不是本人 |
| 追问、连续性、来源记忆 | 保留「造型不能单独作为身份依据」，补上正向规则：清晰吻合时承认为本人 |
| 独立核对 system | 从「客观画面记录器」改为「画面比对器」，允许比对参考与照片，按图输出 `verdict`：`same/likely/uncertain/different/baseline/not_applicable`；禁止相似度分数和编造来源 |
| 核对回传规则与失败规则 | 先回答玩家实际问的问题，身份结论只在涉及身份/外貌时使用；`same` 才承认；核对失败 ≠ 不是本人；不得凭空断言照片来自网络 |
| 核对请求 | `timeoutMs: 240000`（原默认 120 秒，两次真实核对均在此超时，主聊天只收到失败规则） |

`verdict` 为可选字段，缺失时按原行为接受；非法取值按核对失败处理。旧 JSON 契约（`observations/differences/uncertainties`）不变，避免影响既有解析。

### 校准：从「单边放宽」回到正面证据制

首版改完后用微信实拍复测，暴露反向偏差：4 张中 3 张为她时判定正确，但回答成了「第二张好看」的选美；3 张全为陌生人时，三张都被判成「换了发型的同个人」，并各自编出素颜、柔光、幼态妆容、发色变浅的解释。与上一版「没有证据 → 否认」对称，这一版是「没有证据 → 承认」。

已修正：

- **非人物门禁**：核对先判断画面里有没有可辨认的人；风景、食物、宠物、截图、物品写 `not_applicable`，不参与身份比对。
- **规则分流**：全部 `not_applicable` 时改发画面规则，不再向主聊天注入「长相基准/承认本人」，避免把风景照也塞进身份框架。
- **判定收窄**：只有 `same`（清晰可见且稳定特征吻合）才算承认；`likely` 定义为「关键部位被遮挡或画质不足，不足以确认」，主聊天按「看不清是谁」处理，可以问，不能认领。
- **禁止抬档**：脸型、眼型、鼻唇看不到或被眼镜、口罩、暗光、侧脸挡住时只能给 `likely/uncertain`；发型、发色、妆容、滤镜、年龄感、胖瘦、角度不能把 `different` 抬成 `likely`，也不能把 `likely` 抬成 `same`；这些只能写进 `differences` 作解释。
- **先答被问的事**：主聊天规则改为「先回答玩家实际问的问题，只有涉及身份、外貌或照片比较时才用比对结论」，避免「哪张好看」被降级成纯审美题。

对照证据：同一模型在空白卡 `card/chat-ai/Chat-ai.json` 上一次给 7 张图、明确「前 3 张参考、后 4 张待定、禁止联网」，4 张待定全部判对。该任务与微信链路的差异是**任务结构**（单请求、参考与待定同屏、指令直白、无人设干扰），不只是措辞防御性。因此本轮只做判定校准，未改成每次自动附图；关系层反应（吃醋、疑惑）仍待单独设计。

**未处理的已知数据矛盾**：卡面人设写「头发细软，齐肩」，而三张参考图实际是过胸长发。本轮不改人设与参考说明（二者同时服务生图），改由「像素优先」规则消解。若要让卡面与照片彻底一致，需要单独决定是否改人设文字。

回归：微信媒体、生图、参考图、卡身份、场景一致性、RP 插图、世界图片、日志、编辑、世界与备份共 311 项通过；`git diff --check` 通过。真实模型复测尚未进行，因此本轮不宣称「她已能认出自己」。
