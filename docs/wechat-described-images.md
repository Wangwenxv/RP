# 微信离线图片分享与画面描述交接

更新：2026-11-08。沿用原 Vue / 微信 UI，本工程不使用 CWUI。

## 本次解决的问题

RP 主动 `tool_wechat` 原先只接受文字，无法通过同一个工具分享图片。被动微信已有本地相册和简单绘图，但有限图库无法覆盖未来剧情，Canvas 也不适合复杂照片、人物自拍或具体场景。

现在 RP 主动联系和微信回复都能发图片：准确匹配的本地资源显示真实图片；复杂画面或没有合适素材时使用画面描述。描述作为一条 `image` 消息展示为卡片，点开可查看全文，不要求图片 API 或联网取图，也不需要提前为每段剧情准备素材。这里的离线指图片取得和展示能力，聊天模型仍使用原有聊天接口，页面原有 CDN 依赖未改动。

`card/suqixue/tmp.txt` 的旁白回忆了 22:50 发来的北苑路灯照片。这不能单凭文字判定该次未调用工具的原因，也不能把回忆自动补成此刻的新发送。本次补齐后，新发生的分享明确要求模型调用工具，已有历史回忆不重新发送；没有用关键词扫描旧正文、自动导入或改写用户的现有记录。

## 使用与体验

刷新 `index.html` 即可生效，无需重新导入角色或准备新图片。RP 主动联系仍需要角色开启微信，同时启用“主动发微信”工具；开关和每轮一次联系的规则保留。

- 本地相册：沿用真实图片缩略图和放大预览，仍可从原相册入口导入图片与客观画面说明。
- 简单绘图：沿用便签和涂鸦模板，适合角色确实在画画或发纸条的场景。
- 画面描述：显示“图片 / 画面描述”卡片，点击查看全文；不出现“图片加载中…”或失败重试占位，也不伪造发送失败的角色台词。

画面说明描述角色分享的图片内容，并非角色发送的文字配文。例如路灯照片没有配字时，微信中只有图片卡片，不会额外显示“北苑宿舍楼下的路灯”这一条角色文字消息。

## 协议

RP 主动工具一次发送一个气泡，`content` 与 `image` 二选一。图片参数支持 `describe / album / draw`，不通过此工具调用联网搜索或付费生图。

```json
{
  "image": {
    "mode": "describe",
    "description": "北苑宿舍楼下，一盏路灯照亮台阶，树影落在墙上。",
    "usage": "scene_photo"
  },
  "reason": "分享此刻看到的景色"
}
```

可选 `sendAt` 沿用剧情时间解析，表示实际新发消息的时间，不能借此补造过去未记录的联系。发送者固定为当前角色；不接收 `sender / role / messages` 等字段。成功排队返回 `queued: true, delivered: false, awaitingPlayer: true`，结束自动工具续写，整轮 RP 收尾后打开微信并播放，等待玩家回应。图片与文字遵守相同交接规则。

被动微信使用原消息数组，可与文字混排，每轮最多一张图片：

```json
{
  "messages": [
    {
      "type": "image_request",
      "media": {
        "mode": "describe",
        "description": "窗边的木桌上放着一杯热茶。"
      }
    }
  ]
}
```

`description` 最长 240 字符，`describe` 模式要求非空。其它图片模式也可带同一字段用于资源失败兜底；成功取得真实资源时仍使用资源实际画面说明，不以模型提供的兜底描述覆盖它。

主动图片格式由本轮工具 schema 与系统说明直接提供，同时提供本地候选的真实 ID。被动微信仍按本轮发图关键词或 `tool_load_image_sending` 加载完整格式与相册；普通确认和收尾不强迫发图。

## 数据、上下文与失败边界

描述最终存储为：

```js
{
  type: 'image', content: '',
  media: {
    descriptionOnly: true,
    caption: '画面描述全文', captionSource: 'narrative',
    source: 'description', usage: 'scene_photo'
  }
}
```

它没有 `assetId`、Blob 或图片字节，记录随当前角色/剧情分支的 `wechat_timeline` 保存。复用原图片批次与任务 ID，刷新后的未完成描述消息可重试并去重。恢复任务时实际原件已丢失且原请求带描述，也可直接使用描述，无需重新生图。

微信历史、RP 回灌、前情提要素材与保留原文共用 `imageRecordText`，输出：

```text
[图片 #消息ID｜画面描述：…｜叙述画面，无实际像素；不是发送者的文字配文]
```

这保留图片这一事件与画面内容，同时保留人物知情来源：模型读到背景不等于人物已经读过手机。未描述的细节仍未知，不能用识图工具补造。只有实际图片提供 `tool_view_image`，描述型图片不进入视觉附件，也不能读取像素；描述被导入为玩家图片时仍遵守这个规则。

相册缺失、来源未开启或取得图片失败，原请求带描述时使用描述兜底；没有描述则保留原失败/重试流程。中止、切换会话和存储事务/空间错误仍报告或停止，不能被描述兜底掩盖。描述任务本身也必须保存成功才继续播放。

原“清空本段 / 清空全部 RP + 微信”同样处理描述消息及待发送任务。清空涉及图片的内容时，相关前情提要按统一清空规则作废。相册资源与其它分支记录的保留范围见 [清空功能交接](./conversation-clear.md)。
