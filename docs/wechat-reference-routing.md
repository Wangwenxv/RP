## 问题与已完成的改动

玩家陆清淮发“我到啦”和照片，苏祈雪可能只承接照片中的表情，没有核对照片外貌与人物设定。此前聊天模型能读参考图目录文字，参考像素主要给生图服务；`tool_view_image` 只读取聊天附件，没有读取角色参考图的入口。

现在原单卡微信提供 `tool_view_character_reference`，由模型按需调用，并在照片相关上下文提醒核对外貌。普通文字轮不自动附参考像素。人物参考与玩家照片分别标注来源，照片发送者不自动等于拍摄者或画面人物；参考照片中的背景、服装、设备不自动变成本轮现场。

核对的是可见外貌与角色设定是否相容，需考虑视角、光线、画质和允许偏差。明显不相容时可以自然询问，不由一句“我到了”推定照片就是角色本人。提示与工具帮助模型取得依据，仍不能保证任意模型都会调用工具或作出正确判断。

## 批量工具与费用

```json
{"referenceIds":["ref-061791f7792bf56b","ref-e30f6e9690215983"],"messageId":"聊天图片ID","question":"可见发型与角色设定是否相容？"}
```

工具名为 `tool_view_character_reference`。`question` 必填，最长300字符；`referenceIds` 可省略，默认取全部人物图；`messageId` 可省略，指定时只能读取当前角色、当前分支的微信图片。只有地点图时需明确给出地点参考 ID。

不限制本轮参考ID数量或查看工具次数，同轮缓存已读像素。顺序变化和重叠选择不会重复读取或重复附上同一参考图；同模型配置下，同一参考选择不因换问题而增加内部识图请求。本轮玩家新图已经在视觉附件中，`tool_view_image` 再查它只返回提醒，不重新读图或调用识图模型。历史图可用 `messageIds` 一次批量取得，消息ID仍须属于当前角色、当前分支。

| 配置 | 一次批量参考工具的典型完整流程 | 模型请求数 |
| --- | --- | --- |
| 未配置 `visionModel`，或与 `settings.model` 字符串完全相同 | 聊天决策 → 本地取参考像素 → 聊天续写一起看新图与参考图 | 通常2次 |
| `visionModel` 非空且与聊天模型不同 | 聊天决策 → 独立识图一次接收参考图与指定待核对照片 → 聊天续写收到短结果 | 通常3次 |
| 普通下一轮，无需工具 | 仅文字历史与短图片描述 → 回复 | 通常1次 |

两次请求的前提是一次批量工具和有效的最终回复。原有位置/图片格式修正仍可能额外请求一次；其他检索工具、第二次查看以及网络重试也会增加请求。独立识图配置下，要一起比较聊天照片必须传 `messageId`；没有传时识图请求只包含所选参考资料。不同问题可能再次请求独立视觉模型，缓存不把先前问题的答案充当新答案。

最终回复修正机制保留，也没有自动对生图结果做付费视觉复核或循环重画。2026-11-24已解除微信固定4/8次主请求限制，持续到最终回复、请求失败或用户停止；独立识图和底层网络重试另计。当前轮多次续写仍会重复传入已读临时图片和工具结果，不代表没有费用或上下文开销。

`src` 支持网页相对路径和 HTTP(S) URL。相对路径基于**当前网页地址**，不是导入 JSON 文件的目录；路径用 `/`，有空格或中文时应 URL 编码。`file:///`、Windows 绝对路径、带账号密码的 URL 不接受。跨域 HTTP 图片还需图片服务允许 CORS，才可通过 Canvas 取得像素；预览能显示不代表一定能用于识图。

卡片目录和文字聊天不解析路径为 base64。实际识图/生图时才经 `RPHubWeChatMedia.rasterize` 读取、缩放与转码；所得 `dataUrl` 只属于该次请求，不回写角色卡。路径打不开就报错，生图不会在参考读取失败后先调用付费接口。

磁盘 `card/suqixue/苏祈雪v2.json` 为 **97,527字节**，三张参考改成 `card/suqixue/sqx1.jpg`、`sqx2.jpg`、`sqx3.jpg`，保留原说明与人设。工具脚本 `attach-image-references.cjs --linked` 可生成项目相对路径；不加 `--linked` 仍能保存内嵌图片。

刷新页面即可加载新的工具路由。浏览器里以前导入的卡不会随磁盘文件自动更新：旧内嵌卡仍兼容，若要缩小该存档的卡体积，需要导入更新卡或更新其参考资料。参考功能不依赖开启生图或配置生图 Key。

路径引用随卡片、世界包和备份保存的是链接，**不会自动打包链接指向的图片文件**。移动项目、发布到新站点或迁移备份时要一并部署资源，或使用可访问的 URL。新图片上传仍沿用内嵌保存方式，不承诺所有角色卡都自动变成小文件。
