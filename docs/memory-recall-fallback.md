# 记忆总结与向量召回故障降级交接

日期：2026-11-07。沿用工程现有 UI、折叠设置、基础/增强模式切换及提示样式；本工程不按 CWUI 改造。

## 报错定位与功能边界

用户截图中的旧提示「记忆召回失败，本次仍使用总结上下文」来自 `assets/js/app/16-memory-extraction.js` 的 `selectEnhancedMemories()` 异常分支。RP 的 `15-generate.js` 只在记忆开启且模式为 `enhanced` 时调用它。该函数请求的是向量接口，不是总结接口；提示出现时，已经组装的总结上下文仍用于主聊天请求。

仅凭这条提示无法确定服务端的具体错误。常见原因包括：当前 API 不支持 embeddings、所选向量模型无权限/不可用、网络或跨域问题、超时，以及响应内容不完整。没有证据表明这是微信、地理工具、图片或 UI 面板功能互相冲突。

| 功能 | 请求/作用 | 是否修改聊天原文 |
| --- | --- | --- |
| 基础模式 | 总结模型经 `chat/completions` 为每轮生成记忆；超过保留楼层后，用总结替换上下文中的旧 AI 正文 | 否 |
| 二次压缩 | 更早的完整总结组进一步合并；当前为最近 25 轮之外、每 5 轮一组，保留源总结和消息引用 | 否 |
| 增强模式 | 在基础总结之上，经 `embeddings` 索引「用户原输入 + 本轮总结」，用最新玩家输入召回相关片段 | 否 |
| 前情提要 | `26-recap.js` 独立压缩 RP/微信交错历史，按覆盖边界排除重复上下文；此流程未改动 | 否 |

因此，「只压缩之前的对话」应使用基础模式。增强模式另外需要向量服务，普通聊天模型不能代替向量模型。目前向量请求仍复用全局 API 地址和 Key；本次没有增加另一套服务商配置。

## 本次修复

1. **向量故障不阻断总结。** 去掉增强模式缺少向量模型时对整批总结及单条总结重试的拦截。批量向量索引失败单独处理，继续执行二次压缩；单条总结先保存并提示成功，再尝试可选索引。向量失败不会再显示为「总结重试失败」。总结模型本身的错误仍正常报告。
2. **提供具体错误。** 在原「向量模型」字段下面显示故障原因、总结可继续使用的说明和「下次请求重试」。网络连接错误给出网络/跨域检查提示，其他错误保留精简后的接口信息，隐藏当前 API Key，按文本插值显示。
3. **失败冷却和提示去重。** 同一角色、分支和向量配置失败后暂停向量召回及后台索引 60 秒；冷却到期后由实际聊天/补录按需重试，不创建后台定时请求。同一次连续故障只弹一次提示。成功后清除故障状态；修改 API 地址/Key、向量模型、模式或角色/分支也会清除状态。
4. **重试语义。** 「下次请求重试」只解除冷却，下次聊天或补录才实际请求接口；手动「补录记忆」也会解除冷却。需重建缺失索引时使用补录，单纯解除冷却不会主动建索引。
5. **限制主回复前的向量等待。** 查询向量的响应超时为 15 秒，避免沿用通用 120 秒预算拖住主聊天。批量索引继续使用通用 120 秒无响应超时，长回复和主聊天传输规则没有改变。
6. **检验向量响应。** 多输入必须有完整且唯一的 `index`，允许返回乱序后排序；单输入允许省略 `index`。拒绝空、非数值、全零和维度不一致的向量。查询维度与既有索引不符时标记不兼容索引待重建，保留总结及其原文引用，提示补录。
7. **取消与作用域防护。** 已取消的请求继续传播 `AbortError`；返回旧角色、旧分支或旧配置的结果不更新当前召回状态、不写入新配置索引。后台补录 watcher 也补上 API Key 变更的中止处理。

`memoryRecallState` 是瞬态 ref，不进入 `memorySettings`、角色卡、聊天历史、微信时间线或 IndexedDB。持久化结构、模式选择及已有记忆保持兼容，无迁移步骤。
