# 微信剧情时间交接

日期：2026-11-06。本次保持工程原有微信 UI，不使用 CWUI。

## 使用方式

输入区新增「剧情时间」与「同一时间发送」按钮。点击可选完整日期时间，也可使用自定义快捷时间标签。默认提供 5 分钟、30 分钟、1 小时或 1 天后，点击「＋ 添加标签」填写正整数分钟数（例如 15、90）和可选名称；不填名称自动显示「15 分钟后」。点击「管理标签」可编辑或删除任意标签，包括默认标签；允许删空，之后仍可添加。标签自动保存到当前浏览器，所有角色/分支共用。

点击标签以当前剧情钟为基准设置下一次发送时间，选择只暂存到下一次发送，发送后自动恢复沿用当前时间；可用 × 取消。添加、编辑、删除标签只修改快捷选项，不推进剧情时间。文字、图片、文件、表情包共用这项选择。同一次发送的文字与附件使用同一时间。

**连续发送视为同一时刻。** 既有连发模式仍然只落气泡，点击「让对方回复」后才请求模型。相邻同角色消息继续合并，不因时间改变而拆成更多 API 消息：一个合并文本里，只有首条与时间变化处带时间头。

例如模型实际看到的一条用户上下文：

```text
【发送时间：2023-08-01 18:00:00】
1
2
【发送时间：2023-08-01 19:00:00｜距上一条 1小时】
3
4
```

同一时刻的用户/角色往返也沿用最近的时间头。前端仍逐个气泡展示，每组时间居中显示；时间推进时新增分隔，悬停气泡可查看完整发送时间。旧记录用五分钟间隔或跨日分隔，避免把旧现实秒数的差异逐条显示成重复时间。

## 剧情起点与 RP 互通

- 最新 RP 正文首行含完整公历时间戳时，可继承到微信，例如 `【2023年08月01日 07时】`、`【2023年08月01日 07时36分】`、`【2023-08-01 07:36】`。只从首行取，不从正文提到的明日约定、台词等猜测。
- 新的 RP 时间晚于上一条微信时，以它作为下一次发送的剧情时间。比已发送微信早的 RP 时间不倒拨剧情钟。RP 事件顺序继续由统一时间线与 rpIndex 决定，不按虚构日期重新排序。
- `第N日`、缺少年份、古代/架空历法暂不自动换算；玩家可手动设定对应公历日期。不要替模型补造年份。
- 尚无已确立剧情时间时，默认起点为 **2025 年 3 月 11 日 18:30**，玩家可直接选择任意剧情日期；旧现实记录首次转入剧情日期时也可重新锚定。首次写入 `storyAt` 后，同一分支不能倒退发送。
- 打开/关闭面板、现实中过了多久、API 耗时、打字动画都不推进已有剧情时间。

## 模型协议

每个 `messages` 元素可选带以下字段，文字/表情/图片意图/语音意图均支持：

```json
{
  "messages": [
    {"type": "text", "content": "刚才有点生气", "delayMinutes": 60},
    {"type": "text", "content": "现在好些了"},
    {"type": "text", "content": "睡醒再说吧", "sendAt": "2023-08-02 08:00:00"}
  ]
}
```

`delayMinutes` 是相对上一条消息的剧情分钟数，首条以本轮剧情钟为基准。`sendAt` 是完整公历日期时间，两者同时出现时绝对时间优先。未填写、无效或倒退时间回退到当前时刻；不会把 JSON 字段显示在气泡中。时间按批次顺序确定，再准备媒体，媒体耗时和任务重试不重新计算已经确定的时间。

模型选择未来发送时间时，页面保留原来短打字动画，直接推进剧情钟，不会让用户现实等待一小时。不是后台定时投递系统，也不会在玩家下一次发言时补发未生成的中间消息。

`messages:[]` 保持空回协议，不发气泡、不推进剧情钟。沉默记录另存当时剧情时间，下一次请求会带「距离上次沉默的剧情间隔」。模型可据人设考虑冷静、忙碌、睡眠与情绪变化，时间经过不能凭空解救角色或归还被收走的手机。

## 存储与实现

微信消息新增 `storyAt`（数字），仍保留原 `ts` 作为现实创建时间。`storyAt` 用 UTC 日历字段编码虚构年月日时分秒，**不是现实 UTC 时间戳**，解析与显示不受浏览器时区变化影响。旧消息无 `storyAt` 时仍用原 `ts` 的本机日历兼容显示；不批量改写旧记录。

剧情钟由当前角色/分支的 `wechat_timeline` 重建，不新增全局钟。关闭、重开、刷新恢复已发送记录的时间；切角色/分支清掉未发送的选择，使用对应分支记录。删除消息后以当前剩余历史重建时间，不保留一个脱离分支的全局游标。快捷标签另存全局键 `wechat_time_tags`，格式 `[{id, minutes, label}]`；只有无数组存档才提供默认标签，空数组表示用户主动删空。首次打开时间选择时加载，保存成功后才更新界面，失败保留原标签及编辑草稿。

| 文件 | 职责 |
| --- | --- |
| `assets/js/wechat-time.js` | 严格日历解析、剧情钟起点、RP 首行取时、回复时间元数据、相邻消息时间标记与间隔 |
| `assets/js/wechat-protocol.js` | 注入时间规则，归一化各消息类型时保留 `sendAt` / `delayMinutes` |
| `assets/js/app/25-wechat.js` | 发送时间选择、消息写入、回复时间确定、合并历史、RP 回灌、沉默间隔、前端分隔与作用域 |
| `assets/js/app/27-wechat-media.js` | 相册发送使用同一选择，媒体准备/任务恢复保留确定的时间 |
| `assets/js/app/26-recap.js` | 压缩素材与保留微信原文同样按时间分组，裁剪后的首条重新补时间头 |
| `index.html` / `assets/css/wechat.css` / `assets/js/app.js` | 原风格时间按钮、选择弹窗、模板暴露 |

加载顺序新增 `wechat-time.js` → `wechat-protocol.js`，均在应用模块前。单元测试里直接加载 25 模块的 VM 也必须先加载时间服务。独立协议测试未加载时间服务时仍兼容旧格式。
