本轮请求有 11 条 messages，content 合计 45,822 个 JavaScript 字符。最后一条具名玩家输入 338 字，已经独立于角色资料、世界书和提要，未再附加旧 next_response/player_turn_boundary。前一轮消息去重已生效，这次不是玩家消息又被程序规则混在一起。

玩家输入已经写到两人赶完论文、决定往贝岗街走、看到街上的学生，并给出“也许某天带祈雪来看看”的想法。这些内容可以承接，不等于授权模型继续办理入住、洗澡、写微信或决定之后的安排。

返回附带的模型分析明确选择了：

> 用户没要求切视角，先聚焦陆清淮这边。

随后正文新增玩家递身份证、找换洗衣服、洗澡、充电、躺下、打字又删除和新的内心计划。这是**生成任务选择错误与代写玩家**；问题不只限于角色发出微信。同伴作为 NPC 可自主行动和说话，但其选择不能自动带动玩家完成整个流程。

另一处可核实的来源错误是：请求中的“明晚再说”出现在 RP 当面对话及其摘要，返回将它改写为微信界面的最后一条来信。过去凌晨聊天的回忆、红豆沙偏好等也无法从本次请求核实。不能用这些未核实旧事证明人物曾收到消息、已有约定或知道玩家近况。

这份实际返回证明之前的“允许切到NPC”“不代玩家行动”等通用约束仍会被模型违反。它不能证明温度、某个预设或某条角色设定是唯一原因；保持同一模型与温度，再观察新规则的效果。

## 采用的行为边界

| 玩家输入的用途 | 默认续写对象 | 回应点 |
| --- | --- | --- |
| 仅更新玩家独立世界线 | 角色或其他NPC的同期生活与事务，自行选择镜头，无需另行要求切视角 | 无须玩家参与时，NPC片段可完整展开 |
| 正在与NPC直接互动 | NPC这一轮的回应及客观结果 | 玩家下一次发言、选择或行动前停下 |
| 明确委托代写玩家的指定行为 | 只在授权范围内代写 | 不延长到未授权行为 |
| NPC自然想联系玩家 | 角色通过真实微信工具提问、关心、分享或求助 | 一次主动联系成功后，交给玩家回答 |
| NPC事情需要玩家介入 | 创作兼容世界观的事情，呈现情况、请求或线索 | 不预先写成玩家已经参与、解决或答应 |

人物卡定义人物和背景；它不要求所有NPC、事件或镜头围绕该人物。模型负责非玩家人物和有限的世界叙述，玩家只控制自己的言行。

世界可以继续运行：朋友可交谈、办事、惬意相处或休息，不必每轮制造变化、事故或恋爱互动。角色已睡着或无法通信时，保持已有状态，不为了回应玩家在别处的活动强行唤醒。新NPC活动可以创作；旧通信、与玩家的共同经历、已确认约定则须有来源。

以玩家最后写出的动作、位置与时间为其**最后已知终点**。模型可简短呈现既定事实，但不倒回开头重演，也不自动补完未写的合理后续。NPC世界线推进时间不意味着玩家同期已经住店、睡觉或回复消息。

世界事实、读者看到的旁白和人物知情仍分别处理。NPC不会因模型看到玩家输入就知道玩家在另一处做了什么。历史RP台词保持当面对话来源；需要确认具体旧消息或约定时，使用现有原文检索，查不到保持未确认。

## 实现

初版镜头修正集中在 `assets/js/built-in-content.js`，真实验证后又补充了请求布局、历史类别与当前时段：

1. **本体 RP 叙事范围**：buildRpNarrativeScopePrompt 使用当前双方姓名，明确分线默认镜头、玩家终点和三种输入用途，提供办理入住/洗澡/打字删除的边界示例，区分历史RP与微信。由 buildPlayerAgencyPrompt 的 RP 分支注入，独立于COT和可选预设开关。
2. **COT**：情景分析先区分玩家线更新、直接互动和明确代写；规划先选择非玩家事务，保留授权例外；最终检查识别是否仍替玩家完成整段生活流程。保留分析标签、记忆、UI面板及变量协议，合并了原来重复的规划说明。
3. **去User中心化预设**：默认承接NPC生活，明确无需用户要求切镜头；惬意相处、休息和小事也可成立。没有修改人物人格或世界书。
4. **固定准备对话**：保留四条消息及 READY 流程，将 AI 2 原来“从最后真实事件接着写”“用行动让局面变化”的引导改为确认玩家终点、选择NPC事务。COT预注入开/关两条路径均覆盖，不以删除准备对话解决问题。
5. **靠近输入的短任务**：`15-generate.js` 在完整本体 system 之后，将一条短 `rp_turn_task` 插在最新真实玩家输入前。已报告完整的NPC对白不自动成为待续互动；玩家没有发送的新微信也不能由模型先编出来，借此触发NPC回复。
6. **历史类别与时段**：提要/RP原文/微信原文有内部 `_storyArchiveKind`；标准化与组装保留，API 映射剔除。短任务提示本轮是否单列微信原文。剧情时段只解析真实玩家原文里的独立完整时标，排除世界书、摘要、引用和代码，不写回剧情钟。

现有 `23-lifecycle.js` 在加载时同步内置预设，并按开关生成动态COT/准备分析；本次没有改动其保存格式或开关行为。即使已保存旧版去User中心化，最后组装的本体 system 仍提供新默认镜头规则。

保留 [请求规则去重](./request-prompt-dedup.md) 的消息分离与 system 注入方式，不把完整规则再次附到玩家 user 消息。没有增加意图分类模型、正文自动删段、额外联网请求或UI模式开关，也没有改动用户的真实模型或温度设置。
