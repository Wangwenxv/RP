本轮承接 [生活需求预取](./geography-everyday.md)、[地图管理](./geography-map-manager.md) 和 [地点场景预取](./geography-scene-prefetch.md)。保持原有 Vue 页面及微信协议，没有修改角色卡人格、世界书或聊天记录。

## 问题与数据依据

截图中玩家连发“衣服到了”“去快递站找一下”“知道哪里取快递吗”，角色回答“又康那边”。旧版只预取日用品、跑步；地图搜索虽存在，但主要匹配名称、功能和少量服务词，结果缺少场景介绍。活动中心的简介与生活区背景又分别把快递点写在活动中心和一饭后，原图上的独立服务标注没有建点。截图不能证明程序抛了异常，但数据与召回存在明确缺口。

原图 `card/江大南校区.jpeg` 标有一饭后快递点、二饭后快递点、师苑快递点。用户确认一饭后和二饭后两片都是不同快递商家以摊位、小棚子形式开展的聚集地，常见中通、菜鸟等，没有统一正式名称。

- 保留“一饭后快递点”“二饭后快递点”作为地图定位标签，增加“快递聚集区”别名和说明；这些标签不是正式店名。
- “中通”“菜鸟”可检索到上述两片区域，不绑定某个固定棚子或断言某包裹属于其中之一。收件通知决定具体区域与摊位。
- 师苑快递点来自原图；没有把用户对两片区域的说明扩写成师苑也有这些商家或同样的棚子布局。
- 又康继续承担日用品超市用途。活动中心不再承载整片生活服务；删除错误的快递位置及营业时间描述。既有快递“20:30关门”缺乏独立依据，没有迁移到三个点。

本轮共增加15个原图服务点：三处快递点、五处打印/打印照相点、一处照相点、两处电脑手机维修点，以及文具、面包、理发、水电空调充值点。内置地图现在有70个场景地点、17个道路节点、91条边。

## 可维护的数据

每个内置场景地点都有一个或多个 `keywords`。字段含义分开：

| 字段 | 用途 | 示例 |
| --- | --- | --- |
| `aliases` | 地点的其他叫法，可用于地点定位 | 一饭后快递聚集区 |
| `keywords` | 用途、口语或业务检索线索，不作为位置证据 | 取快递、拿包裹、中通、菜鸟 |
| `services` | 资料确认的服务 | 快递取件、打印 |
| `usage` | 使用习惯及需要核对的事项，最多180字符 | 根据收件通知确认区域与摊位 |

`keywords` 可选，最多32项，每项1—40字符；旧地图不含它仍兼容。地图编辑器沿用原表单新增用途关键词、服务、使用说明，编辑搜索和只读地点浏览使用同一套检索。导入、导出、保存、IndexedDB载入及整库备份中的地图准备过程保留这些字段。

仅因“打印”而召回复印/证件照等相关业务候选，不表示已确认全部规格；服务与介绍仍以原图及用户提供的信息为准。没有补造价格、库存、取件码、棚号或实时营业信息。

## 搜索与请求前预取

`tool_geo` 已明确向模型提供“目的地未知先按用途搜索，地点已知用context查路程”的流程：

```json
{"operation":"search","query":"取快递"}
```

```json
{"operation":"search","query":"中通"}
```

默认最多8个结果，每项包括地点ID/名称、片区、用途、短介绍、使用说明、开放规则和 `match.fields / match.terms` 匹配原因。`detail:full` 按需返回完整局部及所属片区介绍。仍遵守brief 6000字符、full 12000字符预算及同轮调用去重。

排序优先地点名称及别名，其次显式用途关键词和服务词；既有 `everyday.needs` 的惯例候选用于补充与稳定排序。功能、使用说明、场景正文可以在主动搜索时提供低优先级匹配，不搜索整个片区长文，以免所有生活区地点都因同一段背景命中快递。

空查询返回 `needs_query`，未收录返回 `not_found`，并要求澄清，不能借超市或活动中心替代未知服务。

`RPHubGeography.search(world, query, options)` 是共用纯本地函数；自动预取使用 `metadataOnly:true`，只靠显式名称、关键词、服务和需求触发，不扫描场景长文触发普通聊天。它支持“你知道哪里取快递吗”等包含已知关键词的口语，无需额外语义模型、向量索引、联网或地图识图API。

RP仍只读取本轮最新玩家文本；微信读取当前未回复的文本批次，最多8条/4000字符。现有 `everyday` 增加取件和吃饭候选，继续提供从角色最近确认位置出发的往返成本。其他地点的关键词命中进入 `placeSearch`，最多补充4个尚未由明确地点或生活候选覆盖的简介，需要移动时再查context。角色自己保存的地点经历只补到本角色对应地点，search结果也已接入这条链路。

内置地图移除每轮固定注入的又康/跑步常识，这些信息改由命中用途后的地点说明提供，减少普通对话中无关超市资料的影响。自定义地图的 `everyday.knowledge` 字段仍可用于确有必要的短公共知识。

关键词召回是候选准备，不是行动命令。否定、引用、假设也可能召回相关候选，句意由主模型处理；程序不据此移动人物。包裹到达不代表已经取到，知道地理资料不代表角色已经获知收件码。

## 路网与更新

新增服务点坐标根据原图红点/文字估算，以叶节点接入附近既有地点；原有地点坐标、76条道路及13栋→实验楼A区约35分钟标定保持原值。新增短边标为示意图估算，允许骑车行程但最后一段下车步行；不表示能骑进店，也不包含排队和办理事务时间。精确入口和实时道路情况仍需核对。

使用内置地图时刷新工程即可取得新版数据，无需重新导入角色或清空聊天。浏览器中保存过的同ID地图或导入副本仍优先使用其自身数据，不自动覆盖玩家编辑。

旧内置地图的本地修改/导入副本旁新增 **创建内置新版副本**：

1. 地图与地理环境 → 旧地图卡片 → 创建内置新版副本。
2. 在角色编辑 → 地理环境中选择新副本并保存角色。

副本从当前工程内置世界及原图创建，使用新ID；旧图、旧图修改和角色当前绑定均保留。该功能不会自动合并自定义路网，需要保留个人设定时可对照新副本编辑旧图。
