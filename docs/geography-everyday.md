## 本轮范围

- 两类需求：补日用品、日常跑步。触发词包括洗衣液/洗衣粉/牙膏/纸巾等，以及跑步/夜跑/晨跑/慢跑/跑两圈等；没有新增意图识别模型、向量库或外部请求。
- 又康成为独立地点`youkang`，别名“又康”。位置按学生活动中心同址接入，路网边的图示长度为0；路线只算到活动中心，不包含店内走动、排队，也不意味着自行车能进店。营业至23:00沿用既有RP设定，不代表当前营业或有货。
- 用户确认：普通学生日常跑步、娱乐通常用假草；真草主要用于校运会、校际比赛、田径队等活动，其余设施相同。更新两处地点用途、使用惯例、短场景和体育片区背景；跑步候选按假草、真草排序，常用地标补假草。惯例不等于禁止普通学生进入真草。
- 当前源地图有55个场景地点、17个路网节点、76条道路。原13栋→实验楼A区35分钟标定不变。
- 没有扩展图上的全部红色服务点，也没有新增打印、维修、快递等自动预取。既有快递位置资料存在活动中心/一饭后门两种描述，本轮不据此做新的服务路径推断。

## 数据与运行时

`world.everyday`是可选共享资料；没有该字段的地图仍能正常使用既有地理能力，且不会混入江大生活常识。

```json
{
  "knowledge": ["日用品通常去又康超市（学生活动中心）；具体库存、品牌和价格未知。"],
  "needs": [
    {"id":"daily-supplies","label":"可能需要补日用品（也可能只是抱怨）",
     "terms":["洗衣液","牙膏","纸巾"],"places":["youkang"]}
  ]
}
```

地点可选字段`services`存短用途词，`usage`存不超过180字符的使用惯例。`search`匹配名称、别名、功能、服务词；命中生活需求时按该需求的候选顺序优先返回。`resolve`仍用于地点名定位，**不会把“洗衣液”当作地点或位置事件**。

`needs`用规范化子串做宽召回：最多2类需求、合计3个不同候选。它只说明“可能相关”，不判断用户是否要求代办，也不做否定、引用、假设等语义解析。例如“今天不想跑步”也可能准备跑步资料，角色仍按实际句意拒绝或聊天；这是轻量版允许的额外召回，不是出发指令。

`everydayContext`从当前角色最近确认位置计算每个候选的步行、骑行成本。起点未知就返回`origin.status: needs_location`，不拿住址或用户位置替代。往返沿两个方向分别寻路；回程不可达时给`returnStatus`，不乘二假造结果。每个交通方式带单程分钟、单程区间、往返典型分钟、估算可信度与道路警告。往返不包括运动、楼内时间和排队，也未模拟活动结束后的天气、临时封路或剧情时间变化。

适配层沿用RP最新一条用户文本、微信当前未回复批次最多8条/4000字符的规则。只有生活需求、没有显式地名或原地理触发词时，准备`locations + everyday`，不额外附通用reach表。与明确地点同时出现时合并进原context结果。

`personal`统一补充当前角色的地点记忆，覆盖工具查询、提及地点预取和生活候选；brief每地点最多140字符，full工具查询最多600字符。又康不会自动继承活动中心的私人记忆，其他角色的记忆也不读取。资料超预算时既有`boundResult`可以移除场景与私人记忆，保留行动成本与状态。

## 模型提示与成本

常驻生活常识最多取前2条。本轮提示要求：候选不强制行动；用户明确指定的地点优先，惯例只补未指定的目的地；可以抱怨、建议、拒绝、帮忙；顺路必须有既定行程依据；库存、临时占用未知，营业以剧情时间核对；地点记忆不自动产生新经历。移动成本可直接使用`everyday.candidates.costs`，短资料够用不重复调工具。

苏祈雪卡生成器和JSON同步把“半小时以上一定抱怨、最后总选离她最近的地方”改成性格倾向：考虑疲劳、手头事务、想见他、事情是否要紧，以及骑车、接送、合并出门等办法。没有建立自动剧情计划或新的长期状态。

以“玩家在13栋、角色在3栋”为位置证据，包含角色现有短地点记忆的地理提示实测如下（**字符数，不是token；不含工具schema及其他角色/聊天上下文**）：

| 最新消息 | 地理提示字符 | 处理 |
| --- | ---: | --- |
| 谢谢啦 | 913 | 短规则、生活常识和位置证据 |
| 洗衣液又用完了... | 1991 | 又康候选与角色出发成本 |
| 陪我去跑步 | 2702 | 假草/真草候选、往返与短地点记忆 |

实际长度会随位置证据、道路警告、地点记忆和同批文本变化。brief资料继续遵守6000字符预算，明确地点＋两类需求的组合也有覆盖。局部计算不增加模型API请求；模型主动补查工具仍可能产生续写请求。

## 使用与已有数据

使用内置江大地图、角色已经绑定该地图时，刷新工程后即可得到新的运行时和生活资料，无需新建角色或删除聊天。

如果曾编辑内置地图并另存同ID，或导入旧地图包，浏览器保存的地图优先于工程内置数据。这些自定义副本**不会被自动覆盖或重置**。可在地图管理的JSON编辑中补入`everyday`、相关地点的`services/usage`和又康节点/同址边；候选ID必须属于这张地图。或导入新版内置地图包，再把当前角色绑定到新版副本。地图保存、导出、导入、刷新载入均保留并校验新字段。

已导入浏览器的苏祈雪卡不会因为重建磁盘JSON而自动更新。需要新的距离倾向时，在当前角色的世界书中替换“共享世界·江大南校区地理能力”条目的距离反应段，或在角色编辑器中更新卡片内容；不要为更新这段而删除已有角色和聊天。共享地图与预取的改动本身无需重新导入角色。
