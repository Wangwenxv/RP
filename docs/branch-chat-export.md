# 单角色全部分支聊天导出、导入修复

日期：2026-11-09。

## 问题与原因

角色导出弹窗中的「聊天记录」下载 `角色名_全部分支_chat.jsonl`。旧版格式 `rp-hub-branch-chat` version 1 仅保存各分支的 RP `chat`，没有读取 `wechat_timeline`；导入端也只写 RP。因此重新导入角色和聊天后，微信聊天、图片、语音、文档不会恢复。这是该入口的功能缺口，和设置中的整库 `.rphub` 备份是两条独立路径。

旧文件没有保存微信，升级不能从旧文件还原微信。若原浏览器、原访问地址的数据仍在，刷新新版工程，在原角色上重新导出。若需要迁移全部角色、记忆、地图、设置及完整相册，继续使用「设置 → 高级设置 → 全部内容备份」。

## 新版覆盖范围与使用

入口与 `.jsonl` 文件名保留，格式升级到 version 2：

- 保存单个角色的全部分支目录、当前分支、RP 原文与完整微信时间线，包含 RP 镜像、剧情时间、空回与未回复的已发送消息。
- 一并保存对应分支已生成的记忆总结/向量记录和前情提要，保持其与原文的消息引用及覆盖关系。
- 保存这些消息引用的本地图片原件/缩略图、语音原件、文档原件/分块/目录/阅读笔记。描述型图片保留其文字；表情消息携带对应图片引用，不依赖导入设备的同名表情库。
- 内置工程图片及远端图片引用仍依赖相应工程素材或远端地址；不会把链接内容自动下载成本地附件。
- 导出前等待当前 RP 和微信保存，其他分支从其作用域读取；只有微信的角色也能导出。生成、附件处理、切换和恢复进行中拒绝操作。

导入前先选择目标角色，再使用原有 `.jsonl` 导入入口。新版文件替换文件中这些分支的 RP 与微信，不改其他角色。附件分配新的 ID，并映射到目标角色与原对应分支，避免跨角色访问失败或覆盖原有附件。目标角色原本未开启微信时，含微信记录的新版文件会一并开启入口并持久化；否则新导入的角色虽然恢复记录，界面仍看不到微信按钮。角色卡的其他字段、API/语音配置、全局设置、未发送草稿和不被聊天引用的相册照片不属于此聊天文件。

导入新版聊天时用文件中同分支的总结和提要替换目标角色的旧派生记录；文件中没有总结/提要时恢复为空，避免旧上下文覆盖新聊天。旧的未完成媒体任务不会重启。记忆功能设置、模型/API 配置及全局数据仍属于整库备份。

旧 version 1 和普通 RP JSONL 仍可导入。version 1 会明确提示文件不含微信，并保留目标角色已有的微信数据，不把缺失字段当成空微信覆盖。

## 格式、接线与错误处理

- 第一行：分支 manifest，`type: rp-hub-branch-chat`、`version: 2`、分支目录及 `activeBranchId`。
- 每个分支一行：`branchId`、`messages`、`wechatTimeline`、`classicMemories`、`storyRecap`。
- 每个附件一行：`type: rp-hub-chat-resource`、`kind`、原 ID、所属分支、元数据与资源内容。Blob 使用 base64 并保存 MIME/字节数；文档分块等保存 JSON。base64 会增加文件体积，大量附件建议使用二进制 `.rphub` 整库备份。
- `branch-chat-utils.js` 负责附件收集、完整校验、Blob 解码与资源 ID/作用域映射。不会根据文件提供的任意存储键写数据库。
- `22-character-io.js` 接入 v1/v2 格式、活动作用域保存与导入后的重新加载；`data-services.js` 的 `setStoredValues` 把所有分支、时间线、附件及资源索引放在一个 IndexedDB 事务内写入，失败整体回滚。
- 同角色/同分支导入也强制刷新微信时间线和图片库缓存；替换会话期间共用会话写入锁与 revision，取消旧定时保存及后台任务。
- 本地附件已经丢失时拒绝导出并说明缺失项；新版缺少时间线/附件、字节长度错误、未知/重复分支、未知资源字段时拒绝导入。不会显示“成功”却只恢复正文。

涉及文件：`assets/js/branch-chat-utils.js`、`assets/js/data-services.js`、`assets/js/app/22-character-io.js`、`assets/js/app/25-wechat.js`、`assets/js/app/27-wechat-media.js`、`assets/js/wechat-media.js`、`index.html` 的脚本加载列表。
